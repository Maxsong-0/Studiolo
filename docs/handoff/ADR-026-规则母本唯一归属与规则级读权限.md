# ADR-026 规则母本唯一归属与规则级读权限

## 背景

用户 2026-09-23 拍板「规则视为重点纳入，单独界面管理，可以添加并且设置权限」；T-132 接续线据此出设计稿 「2026-09-23-T-160-规则管理界面设计」（vault，未同步），2026-09-24 用户对第 7 节 8 问**全按推荐**。2026-09-26 T-130 接手线开工前按 main `4947562` 核实现状，发现两处与设计稿前提不符，决定拆两期：

1. 设计稿写「`_规则/` 自 2026-09-23 进 SyncScope」——main 上 `crates/host-config/src/sync_scope/paths.rs:44` 仍把 `_规则` 列在排除表；纳入只在 T-132 本地分支，未合 main、未上线。生产上 AI 读到的 `_规则/` 文件来自 Mac→169 只读副本，不是 canonical；canonical 仍是「初始快照、持续同步未接通」。所以「effective 机写 canonical `_规则/`」在 T-132 上线前到不了 Mac 与 AI。
2. 人侧程序（`crates/local-server/src/board/auth.rs:51` 读能力集项目白名单）与 agent 都按 `#[serde(deny_unknown_fields)]` 解析能力集：现役程序遇到带新字段的能力集会整体解析失败。

## 决定

**母本与权限（8 问，全按推荐）**

- **D1 唯一母本**：规则只有一个母本——策略平面 `rules` 类 effective（subject 形如 `通用工作规则.md`，命名沿用 `validate_rules_subject`）。`_规则/` 里的文件、`~/.claude/CLAUDE.md` 与各项目 `CLAUDE.md` 都是它的投影。
- **D2 视图**：新增顶层「规则」视图，与「策略」并列；导航由五项改六项：驾驶舱 · 项目 · 文档 · 协作 · 规则 · 策略（T-130 规范第 66、95 行同步改）。
- **D3 权限模型**：能力集 `read` 新增 `rules_whitelist: Vec<String>`（`#[serde(default)]`，元素须满足规则 subject 命名、不得重复）；实例级沿用三级吊销，不另做实例白名单。
- **D4 缺字段即零规则**：旧能力集没有该字段＝一条规则都读不到（失败关闭，与 `deny_by_default` 同向）。
- **D5 两个执行点同一裁决**：策略平面读取（`policy_read kind=rules` 列表与单条、路牌第 5 项的策略规则）与 `_规则/` 文件供给（`read_note`／`list_entries`／`search`、路牌的库文件兜底）用同一个判定；人侧永远全读。
- **D6 首批 subject**：`CLAUDE.md`＋`通用工作规则.md`。
- **D7 投影机写**：允许 effective→canonical `_规则/<subject>` 的机器写，登记为敏感动作「策略投影写入」，主体「策略平面」（**二期**）。
- **D8 顺序**：母本发布（用户在场）→ 后端 → 前端；本 ADR 下改为「一期代码 → 一期上线 → 母本发布」，见下。

**核实后补的派生决定（用户未单独拍板，以本 ADR 为准，可推翻）**

- **D9 规则文件的定义**：直接位于 `_规则/` 下的 `.md` 文件是「规则文件」，文件名即 subject（今天是 `通用工作规则.md`、`SKILL.md`）；子目录（`references/`、`归档/`、`skills/`）不算规则文件，照项目白名单。与是否已在策略平面发布无关——这样 D4 的「零规则」对库文件同样成立。
- **D10 单一裁决点**：agent 侧把规则文件判定收进 `Grant::allows`（`crates/agent-server/src/server/grant.rs:31`），`read_note`／`list_entries`／`search`／路牌组装一律经它；判定函数放 `studiolo-supply`（规则根名与「是否规则文件」只定义一处）。没有策略平面的 M3 兼容模式不做规则过滤（那里本来就没有权限模型）。
- **D11 项目副本不归规则权限管**：`项目/*/CLAUDE.md` 是项目文件，仍按项目白名单；它们与母本的一致性归二期副本漂移（T-149）。已知限制：一期里零规则名单的 AI 仍能经项目白名单读到项目里的 `CLAUDE.md` 副本。
- **D12 人侧不加新接口**：现有 `/api/v1/policy`（状态含每个 effective 条目的版本号）＋`/api/v1/policy/versions/{n}`（取正文）＋ desired／validate／activate 已够「规则列表、新建、编辑、发布、权限矩阵（改能力集 desired）」；设计稿的 T-160d 一期取消。
- **D13 上线顺序（硬约束）**：人侧新发行与 agent 新版**都部署完**之后，才能发布带 `rules_whitelist` 的能力集；否则现役程序解析失败——agent 拒绝一切供给、黑板授权失败。新程序上线到新能力集发布之间，所有 AI 读不到规则（D4），须用户在场连续完成。

## 后果

- 规则第一次有了「谁能读哪条」的机器强制，且与项目白名单同处策略平面、同一 L3 发布、同一审计。
- 一期上线窗口内 AI 暂时零规则（分钟级），换来失败关闭不留缝。
- `SKILL.md` 因 D9 成为规则文件，需写进名单才可读；若不想这样，改 D9 为「只认已发布 subject」即可，代价是未发布前的库文件不受名单约束。
