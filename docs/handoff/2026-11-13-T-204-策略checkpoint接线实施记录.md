实码核实：接入方固定 `agent-data/audit/audit.sqlite3`，人侧为独立配置的 audit 根，不能拿一个 offset 代表两个账本。全局准入按接入方账本→人侧账本排空（接入方可以调用人侧黑板，反向无嵌套写调用）；owner 的七项冻结顺序不变。Audit 水位需明确主账本与接入方附属账本，清单和恢复核对均保留两条完整性链，禁止静默遗漏。

依据：SQLite 官方 backup API 文档要求源与目标不同连接，复制期间保留目标写事务；每次 step 有界页数，外层仍保留跨库屏障。其余 owner 采用该 API 可保留 rowid，避免 VACUUM 重编号影响未知业务引用。引用 https://sqlite.org/c3ref/backup_finish.html 与 https://docs.rs/rusqlite/0.40.2/rusqlite/backup/struct.Backup.html 。
