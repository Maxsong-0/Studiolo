## 存储与唯一 owner

BridgeState 在 `studiolo-sync-bridge` 的独立 `sqlite` 模块内拥有专用私有数据库。
它不是 Control DB 的第二写者，不把 TaskEngine 引入人侧 CanonicalWorkbench。
纯规划模块继续无文件系统、数据库、网络、时钟和随机权限。

配置装配须批准一个与 canonical、镜像、Auth、Audit、writer-data 分离的目录。
目录预先存在、0700、当前真实 OS 用户所有；文件为0600、单硬链接的普通文件。
固定文件名为 `bridge.sqlite3` 和 `bridge.lock`，SQLite 只使用其固定旁文件。
初始化是明确动作；existing 打开不建库、不建租约、不迁移或修复缺失状态。
schema v1、application_id=0，先在一致读事务核验完整结构、有界状态、绑定及
quick/FK检查，通过后才主动配置或checkpoint；错误打开也不在Drop时自动刷WAL。
SQLite自身必要的hot恢复不属于应用补库，不承诺失败打开绝对零I/O。

单实例使用 OS 文件排他租约，所有操作复验根、数据库及租约的固定 FD 和路径身份。
用实际 UID/GID 核对进程身份，打开操作不跟随符号链接且不等待 FIFO。
不假设别的程序会遵守这把锁；生产只能给受信任的 Bridge owner 此目录能力。
已持锁guard在SQLite连接关闭之后显式unlock，再关闭FD；构造中途失败也释放已取得
的锁。真实占用返回Busy，其他锁I/O错误返回Unavailable。保留FD副本的确定性测试
验证重开不依赖最后一个副本关闭；不据此断言此前偶发Busy的具体调度原因。

## 原计划与原回执

唯一活跃计划绑定 link、两侧根、Vault、scope 内容摘要与代次、原完整共同基线、
单调观察序号、计划序号及完整输入。reserve 在同一事务内 CAS 原状态版本，并从
冻结输入重算纯规划结果；不接受调用方提交的任意动作列表。

每条动作的实际外部幂等键在执行前固定持久化。派发须先取得原 Intent 的真实审计
ACK，再持久化 Issued。Issued 后重开显示未知，不用当前目标与拟写内容相同补成功。
后续只按原键、原路径、方向、前置 revision 与请求身份核对原 Broker/镜像终态。
回执里的摘要用于完整性和关联，不能自行证明其来自真实执行者。

结果必须明确为已提交或有权威证据的无效果终态；布尔值、命令退出码、碰巧相同的
文件、当前本地 Sync 成功时间都不能替代原动作回执。可信执行 adapter 属于后续
组合层，不能让 HTTP、frontmatter 或任意 JSON 直接调用结果确认入口。

所有动作结果已知且对应 Outcome/整批结果审计均 ACK 后才允许 settle。
失败或部分成功计划可以终结，但保留旧共同基线。只有全成功、无冲突且获得完整、
更新的双侧共同观察后才推进基线；该观察还须属于当前打开实例，不能跨重启复用。

## 审计、熔断与容量

AuditLedger 是受信任的权威 adapter。固定事件 append 在 SQLite 事务之外执行，
返回后验证完整 AuditRecord 与原事件严格一致，再用原状态版本 CAS 保存 ACK。
崩溃后重送同一事件；不把“调用过 append”当作已确认。

整个计划删除数大于5或超过原完整共同基线存活路径的10%时，先原子保存熔断、
游标及原输入，整个计划不能执行。重开、改分页、新建文件都不能清除熔断。
本单元不提供普通解除入口；后续解除必须经过已登记的 L3 设置/同步动作。

每链最多一个活跃计划、4096个路径/动作，路径最多1024字节。输入最多16MiB，
完整逻辑状态最多64MiB，单回执最多8KiB，审计事件最多1MiB。整数进入SQLite前
检查 `i64` 范围。主库、WAL及SHM的物理预算与checkpoint策略须另行验证，不能
只限定JSON大小就宣称磁盘有界。

reserve还按每条未来动作32KiB、Input、整批ACK、当前last、最长未来基线和退休
记录预留最坏空间；超64MiB整批在任何Issued前拒绝。4096是数量上限，不保证最大
回执组合都可装入。已有动作不能通过丢弃pending腾空间；重开从冻结输入重算预留。

物理配置为主库256MiB、4096字节页；WAL预算包含每帧24字节头及文件头，
写前必须完成TRUNCATE，旧读者阻止时不开始新写。关闭cache_spill，提交后再截断；
提交后失败保留可能已生效的原状态并封闭实例。本机真实SQLite预算/旧读者负测已过，
逻辑预算不等于RSS，也不代表生产磁盘故障已验收。

不可变计划与逐动作可变状态应分开保存；派发、回执和 ACK 不应反复复制或重算
整个计划。全量完整性验证发生在打开、reserve、settle等必要边界；缓存必须与
固定存储身份和状态代次关联，不能跳过漂移检查。

保留活跃计划与最近终态的原始回放。旧终态只有取得明确退休票据及真实审计 ACK
后才进入永久拒绝区间；旧键返回 Retired，永不重新执行或伪造旧成功回执。
无法取得 ACK 时返回容量/退休待处理，不覆盖原记录；未决和熔断不能靠回收消失。
