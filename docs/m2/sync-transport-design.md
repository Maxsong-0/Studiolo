「已认证摄入」专指镜像到 canonical。无需重新决定是否实现双向。
canonical 只能经 Broker 写，镜像与 canonical 分离，正文与大附件均须往返。

ADR-005原“镜像只由headless写”与双向搬运目标存在缺口；2026-09-13已将下述
分阶段写者协调同步至ADR-005/010和权威写路径表。范围仍是同一双向链路，
canonical写者保持唯一Broker；实际SyncTransport尚待实现及实机验收。

三种模式；配置项包括文件类型、配置同步和冲突策略。

这两份命令列表未提供“提交一份本地文件给 headless 写入”的接口；不能据此断言

接口，也不得把 Publish 上传当成私人 Sync。

JSON输出已记入CHANGELOG，0.0.13包含过滤器变更误删的修复。此处只读公开资料，
尚未安装或登录。具体生产包还需固定摘要与隔离验收，不能以主分支文档代替部署证据。
[当前包声明](https://github.com/obsidianmd/obsidian-headless/blob/master/package.json)、
[官方变更记录](https://github.com/obsidianmd/obsidian-headless/blob/master/CHANGELOG.md)。

[Headless执行契约核查](headless-execution-contract.md)。默认 `sync` 即单次，
没有 `--once` 或同步结果JSON；`sync-status --json`仅是本地配置投影。

## 已登记、待实现验证的写者协调

由窄 SyncTransport 统一拥有专用镜像目录及自有 headless 子进程生命周期。
出站内容先在镜像之外稳定落盘，确认自有同步进程退出后，在排他窗口按镜像实际
基线校验并安装白名单内容，再运行同步；临时文件不交给上传扫描。
bridge 摄入逻辑只读镜像，并经唯一 Broker 写 canonical。

镜像由 headless 与受控出站 Adapter 分阶段写的规则已正式登记。
不得暂停用户桌面程序或别人的进程，
不得假定 headless 会遵守 Studiolo 自设的 flock。

暂停本地子进程不冻结远端。后续设计必须覆盖 canonical、镜像、上一共同基线的
三方状态、远端同时更新、删除熔断、未知同步结果与再次下载产生的回流。
同步命令成功不等于某份内容已到达手机；队列出站也不等于冲突已解决。

headless 的特定版本、真实路径与凭证、首次镜像核对、两周试跑和真实设备往返仍须
单独验收。当前只有文档核查；未安装、登录、改配置、同步或写真实 Vault。

## 持久基线、冲突与权限

候选拆为 BridgeState、纯 BridgePlan、SyncTransport 与唯一 Broker 提交入口。
私有 BridgeState 保存 link/remote Vault 身份、canonical UUID、scope 版本、上次两侧
基线、单调观察序号、当前方向和阶段、目标摘要及 Broker 回执关联。不能以内容摘要
单独当幂等键：A→B→A 是新变化；同一未决候选重启则必须复用原键。

| 当前相对共同基线的变化 | 候选行为 |
|---|---|
| 仅镜像变化 | 以 canonical 基线 revision 经 Broker CAS 摄入 |
| 仅 canonical 变化 | 镜像排他窗口内按真实旧基线条件导出 |
| 两侧都变化且字节相同 | 记录新的共同观察；不补某笔未知操作成功 |
| 两侧都变化且不同 | 保留双方，生成稳定且幂等的冲突项 |
| 首次同路径不同内容 | 无可信 base，不选一侧直接覆盖 |
| 首次一侧缺失 | 按明确导入计划 create-only，不解释为删除 |
| 已有共同基线且后续确认删除 | 才能形成带旧 revision 的删除候选 |

[私有整文件范围](sync-scope.md)已通过38项本机契约，默认关闭；实际观察接线仍待实现。

两向共同执行可信白名单与硬排除。策略、运行投影、raw、私有数据不能借冲突副本
进入公共 canonical 或 L0；不可变证据异常需隔离双方并撤销原 manifest 可信状态。
人写工作项不得被投影回滚；混合生成区须先定义投影与回写协议，不能整页复制。

worker 使用内部绑定 link/Vault/scope 的能力，不用浏览器 Cookie 或镜像 frontmatter
声明授权。scope 修改属于矩阵已有 L3 settings/sync。自动摄入、导出、删除熔断解除
及恢复的审计事件和故障语义须在正式计划补为封闭表，不套用人侧保存的审计例外。
审计主体只能证明此链路观察到的“外部：Obsidian”，不能猜测具体手机或个人操作。

## Broker 与恢复前置

- 有界流式 create/replace/history：现有 Vec 与4MiB内存边界不覆盖实际大附件。
  来源稳定校验、流式计数/摘要、自有stage、旧版本历史、同步及水位均由Broker负责；
  不让worker自己写canonical。正式预算需明确字节单位并核当时服务限制。
- CAS删除与可恢复墓碑：保存实际旧内容、持久阶段、父目录同步和水位。重命名可用
  有持久关联的安全复制后删除实现，但不冒称多文件原子事务。
- 删除熔断须在完整计划中的任何删除执行前计算并持久化，不能拆批绕过。首次导入、
  不完整下载、目录消失或扫描失败不得产生删除计划；数量/比例及解除门槛仍需定义。
- BridgeState纳入一致checkpoint。恢复旧canonical配上较新镜像基线必须先重新协调，
  暂停破坏性传播；UUID、配对、scope、水位或基线不一致均不能静默继续。

队列、stage总量、并发、磁盘预留与历史容量均需预算；超限明确显示未同步。
索引新鲜度、两侧协调状态和最后一次transport成功分别报告，不能互相冒充。

T-046的[三方纯规划器](bridge-planner.md)保持独立无I/O；同crate另有严格隔离的
[私有持久状态](bridge-state.md)，macOS70项契约已过。完整显式观察、逐侧CAS、
稳定原键与整批熔断不等于真实字节运输；完整扫描、冲突保全、受控headless与设备
往返仍待接线。默认删除阈值为大于5个或大于原完整基线存活路径的10%。

## 下一片可独立验证的场景

- 首次相同/单侧/不同/下载未完；双向连续10次修改、无重复L0回流及A→B→A。
- 同revision保存与摄入竞争、同时修改、删除对修改、重命名对修改，保留双方字节。
- 入站/出站/回执/镜像安装/同步运行的中断与重开；本地暂停期间的远端更新。
- overflow/漏事件/根替换/扫描失败，完整重扫恢复并保留历史缺口提示。
- 白名单的大小写、Unicode、链接、策略、raw、生成区与证据篡改负测。
- 删除阈值前后、持久熔断、重启/拆批绕过；旧checkpoint对新镜像。
- 42MB规模、精确文件上限及加一、源增长、磁盘满、内存上界与旧大文件历史。
- 无法确认自有headless退出时拒绝安装镜像，并证明不终止其他进程。

正式接入仍需获准Vault/专用路径、首次基准与范围、运行节点和删除阈值。
真实PDF/其他类型、各设备冲突策略、手机可见性、往返与两周试跑不得由夹具代替。
