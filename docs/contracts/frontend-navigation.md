# 浏览器视图位置（T-097）

## 为什么位置要离开组件内存

[浏览器会话入口](frontend-session.md)规定页面隐藏即取消内容、恢复焦点重新核对，
授权代次变化时工作台整棵子树连同原文弹层一起卸载。这条不变：内容必须随授权一起消失。

但「在看哪个视图／哪个项目／哪个面板」不是内容，是位置。位置若只活在组件内存里，
每次重新核对都把人送回默认视图。位置因此写进 URL hash，与内容分开存放：
重挂之后各视图把自己那一格读回来，刷新与分享同一链接也落在同一处。

## 只存位置，不存内容

hash 是一张白名单表，共四格，全部为非敏感导航状态：

- `view`：现行六个视图之一，顺序与顶栏一致——`cockpit`（驾驶舱）／`projects`（项目）／`documents`（文档）／
  `collab`（协作）／`rules`（规则，T-160）／`policy`（策略）。
- `project`：项目 root，项目运作、协作各标签与文档变更流的项目选择。
- `panel`：视图内的面板，如项目的 `operations`、协作的 `timeline`、文档的 `tree`／`changes`、规则的 `edit`／`access`；默认面板不写。
- `item`：面板内选中的条目，如执行任务 id、策略版本号、在编辑的规则名、文档视图里阅读器在看的文件路径。

**禁止写入**：会话凭据、CSRF、owner scope、因子状态与恢复码、笔记正文、搜索词、草稿，以及规则正文与规则草案正文。
这些要么属于授权，要么属于内容，都随重挂消失，不借位置这条路偷渡到 URL 或浏览器存储。
规则名是规则的标识（`_规则/` 下的文件名），不是内容，可以进 `item`。

## 文档阅读器的单文件深链（T-209）

文档视图里打开一篇，路径记进 `item`（`#view=documents&item=项目/…/某篇.md`）；关掉就清掉。刷新、会话重新核对后的整页重挂、
把链接发到另一台设备都落在同一篇上，并且**以地址为准**：地址里的路径没了阅读器跟着关，换成另一篇就读另一篇。

- 路径和规则名一样是标识，不是内容。它是外部输入，只当文本用；读不读得到仍由读取接口照常鉴权，读不到就是阅读器里的普通错误。
- 行号不进地址（从链接打开一律从头读）；正文、搜索词照旧禁止。放不进一格的路径（超过 512 个字符等）不记位置，阅读器照常打开。
- 只在文档视图里记。项目、驾驶舱、⌘K 等别处打开的来源不写地址：那些视图的 `item` 另有含义。
- **编辑器的路径仍然不进地址**：编辑器按 owner scope 和对话框身份管控迟到的导航（`useEditorNavigation`），不能从一条链接直接进编辑态。
- 代价：浏览器历史里会留下看过的文件路径（hash 不会发给服务器）。

实现在 `web/src/useReaderSource.ts`（渲染时由地址推出阅读器在看哪篇，不用 effect 同步两份状态）；测试 `web/src/test/DocumentDeepLink.test.tsx`。

## 旧链接迁移

T-130 之前的七个视图名（`overview`／`inbox`／`documents`／`operations`／`policy`／`board`／`execution`）的链接照样能打开：
其中 `overview`、`inbox`、`operations`、`board`、`execution` 在解析时按
[设计规范](../design/t130-design-system.md)第 4 节「旧链接迁移」表换算成新位置
（如 `view=board&panel=replay&project=P` 落到 `view=collab&panel=timeline&project=P`），
`documents` 与 `policy` 沿用原名。只在解析时迁移，写回 URL 一律只用新名；旧视图没用过的格子不带过去。

## 解析与写入

- hash 是外部输入：未知视图、空 hash、损坏内容一律回落驾驶舱（`cockpit`）并丢弃其余三格；
  单格的空值、超过 512 字符或含控制字符的值按「不是位置」丢弃，绝不原样回显。
- 默认位置序列化成空串，首屏地址干净。
- 写位置用 `history.replaceState`，位置是「回到离开处」的记号，不把后退键变成视图历史；
  禁用 History API 的环境退回直接改 hash。`hashchange`／`popstate` 变化立即被各视图读到。
- 换视图即清空 `project`／`panel`／`item`：三格按视图解释，跨视图会读成别人的位置。
  换项目同时清 `item`：条目属于旧项目。视图内换面板（协作的子标签、规则的面板）只换 `panel`，其余两格留着。

## 验证边界

自动测试覆盖：hash 白名单解析与回落、序列化往返（六个视图）、旧链接迁移、`#view=rules&panel=edit&item=…` 的解析、
会话仍有效时重新核对后回到原视图与原项目、会话失效走登录后回到原位置、带位置的链接直接打开与损坏位置回落。
真实浏览器（虚构预览库）验过：重新核对后回到原位置、刷新、带位置的链接、
401 后登录再回原位置。未覆盖：跨设备同步位置、多标签页之间的位置协商。


## 文档变更面板（T-206）

`view=documents&panel=changes` 打开内容变更流，`project=项目/名称` 固定完整项目范围；
未指定 project 为全库。文档内仍保持搜索/文件树/变更三个子标签，顶栏六项不变。
⌘K「文档 › 变更流」和驾驶舱「最近内容变化」都落到该面板并聚焦项目选择器。

按项目分组呈现可靠主体与外部未知主体，保留缺口提示；本页未读数不能当成全库总数。
显式「将本次快照全部标为已读」经唯一 SessionClient 的 CSRF POST，成功后重取第一页。
未确认结果沿用原请求编号重试；范围变更、切走、会话失效使在途响应失效。

驾驶舱原有四个统计数保持既有语义，增加当前有界窗口的未读前三条内容摘要；与任务事件动态
分别展示，既有 20 秒刷新调度器按次序重读，失败保留原事实并报告刷新失败。未装配端点显示
不可用，不把缺接口报成没有变化。没有新增实时订阅或 MCP 工具。
