# 独立备份作业目录

`BackupStore` 打开一个已批准、当前用户所有的 0700 目录，逐层 nofollow 固定原根，持有固定空 `backup.lock` 的原内核独占 flock。第二个实例或进程不能同时打开同一目录，返回 Busy。进程异常退出后锁自动释放；接管不读取 PID、不删除或替换旧锁文件。

显式初始化只允许创建全新锁和状态；已存在的锁一律拒绝重复初始化，避免在残缺或旧目录里重置单调作业序号。普通打开不补建丢失锁/状态。未上线的旧 Rust 原型状态目录没有租约文件，不能由普通打开悄悄升级。

每次读写前后核对原根和原锁的 inode、权限、所有者与空锁长度。根或锁被替换后旧实例立即拒绝继续读写；即使旧 FD 仍指向被改名的目录，也不能继续写到用户以为已经停用的位置。文件仍为 0600、单链接，状态与最终本地清单沿用固定临时名、fsync、原子替换和父目录 fsync。

该句柄可以转移到专用 worker 线程，但不能跨线程共享；整个作业调度由独立 worker 串行驱动。L2 状态查询须经 worker 接口取得读数，不能打开第二个 BackupStore 绕开独占租约。本地 manifest 持久化仍不等于远端最终 manifest 已提交。

真实测试覆盖：第二进程拒绝、原实例 drop 后接管、持有进程被 kill 后无需删锁即可接管、根/锁替换阻断、链接/错误权限/非空锁/丢失锁拒绝。子进程入口明确 ignored，只由父测试提供虚构根并显式调用；父测试实际验证其退出状态。
