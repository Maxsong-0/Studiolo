# 固定槽因子运行装配（T-023）

`FactorRuntime::attach(sessions, current, replacement)` 为已经登记的 Auth v4
装配一个固定当前秘密和至多一个固定替换秘密。没有新 schema、登记入口或环境读取，
秘密由[T-024可信启动层](auth-factor-http.md)提供。本接口没有权限更改主人配置或访问 Vault。

每个 `step_up / rotate_codes / recover` 先重验会话与 CSRF，再从权威存储的
seed_ref、秘密绑定和登记序号选择活动槽。最终动作继续使用原 TOTP/Recovery
状态机重验、持久预算、消费和审计，不缓存恢复成功或复制秘密派生逻辑。

- 当前/替换引用相同，或不同引用复用相同种子，装配失败。
- 只有当前槽仍为原登记序号时才允许向替换槽恢复；没有候选提前拒绝，不消费恢复码。
- 观察到替换槽后，当前运行实例永久收紧原槽资格；替换已激活时重开直接选择替换槽，
  不把旧当前槽作为反向候选。跨实例变化也逐次重新选择。
- `step_up` 返回原真实近期认证；换发只交付原调用一次恢复码；恢复成功返回空结果，
  全部旧会话和旧近期认证按原状态机吊销，不自动发新 Cookie 或通用 L3。
- 提交后失败可能已经切换；不自动重放。下一次或重开根据存储选槽，补记不提权。

公开行为测试使用真实双 SQLite 重开和跨实例，另覆盖未知/重复槽、没有候选、错误 OTP、
审计权限失败与补记不重放。固定槽检查不抵御管理员一致回滚整库，且不证明外部秘密
平面与 Auth 提交原子。HTTP和可信代理来源见T-024；秘密部署和真实手机配对仍独立验收。
