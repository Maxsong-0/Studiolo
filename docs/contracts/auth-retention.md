# Auth v2：有界保留与显式迁移

状态：2026-09-05 T-014 已通过 macOS/Linux aarch64 契约验收。补充 [会话契约](auth-session.md)，不提供 HTTP、TOTP 或真实身份登记；尚未合并部署。

## Interface 与失败边界

`SessionManager::maintain_retention()` 是受信任后台入口：每次最多16个终态及16个 epoch 前缀，不接受任意待删对象。内部仅一个持久计划及一个替换式检查点。读取、签发与吊销不隐式运行清理。审计依赖同步，数量有界不等于墙钟期限。

维护仅清理已经持久终态，不自行采时钟或触发到期；到期仍由 open/check/issue 等原生命周期入口检查。返回 `RetentionReport { reclaimed_sessions, remaining }`，remaining 为 None/More/AwaitingDelivery；审计故障可在已完成部分交付后返回错误，重试不得重复授权或增加删除范围。

T-018专用`issue_enrolled`在初检真实主人/登记的`run`中先观察到期，再显式调用一轮上述维护，之后重新验证的签发；不改变原issue/read/revoke语义。没有定时后台或无限循环，实际成本与失败模式见[HTTP契约](auth-http.md)。

先保存不可变计划；事务外重放原事件，要求原始精确回执不变；再确认稳定 `session.compacted` 清理许可。最终 Auth 事务重验同一候选并原子删除和替换检查点。许可不是已删除结果；故障可留下许可而未清理，重试继续原计划。active、pending、未确认或仍有依赖的证据均不删除。

`epoch_base` 不大于剩余会话最小 epoch（无会话则 current epoch）；连续保留 base+1..current 的 all-revoke 双阶段证明。推进前缀需确认被删事件。旧序号不复用、迟到签发/补记不能复活。完整历史保留在 AuditLedger；Auth 不承诺对抗管理员一致重写、整库回滚或克隆并行写入。

## v2 身份与凭证

- 签发序号为持久正 i64，在外部 intent 前预留，失败可烧号，溢出失败关闭。
- ID 为 `v2-<16位小写hex序号>`，与旧32hex不相交；原 issue/revoke/expire 事件命名结构保留，携带新ID。
- 传输值为 `s2.<16hex>.<64hex>` / `c2.<16hex>.<64hex>`；仍兼容旧64hex。完整规范编码入域分离摘要。
- 独立32字节种子经 HKDF-SHA256：salt=`studiolo-auth-v2\0`；info=store_id原始16字节 || BE64序号 || 用途字节1/2；L=32。只交付派生输出，原种子不持久化、不交付。保留行持有用于跨域重复检测的种子摘要。
- v1 原始随机值曾直接交付，因此迁移冻结全部旧两域摘要，最多1024对、之后不增长。新种子按两个旧域比较该集合，命中拒绝。不能声称 HKDF 修复已知、低熵或可预测 RNG。

## 迁移

普通 `open` 不隐式迁移；`migrate_v1` 在完整校验后单事务建立 v2 附加表，保留原 owner、ID、摘要、回执、状态、有效期、时钟地板及序号。无数据清除或新授权，不另发迁移授权事件。未知格式/损坏/配置不符拒绝。迁移后旧二进制应停止写入并失败关闭；不强制已有活跃会话重新登录。

格式事务内部失败会回滚；事务成功后，后续打开检查或时钟回退仍可能让方法返回错误，此时库可能已是合法 v2。修复外部条件后幂等重开，不重新迁移或重发旧凭证。

逻辑记录预算固定；SQLite 文件/WAL 高水位与权威审计持续增长不等同于 Auth 行数无界。真正生产接线仍需维护调度、运行检查和后续 M2 门禁。
