# 独立备份作业的审计通信

T-204，2026-11-13。已实现封闭消息、单作业生产者端口及已连接 Linux UDS 的帧传输；
原生 WorkerAuditClient 已接固定 root 配置的 socket，生产者已实现原账本上的持久准入；
尚未接入常驻 worker、固定路径监听器、完整调度或生产双 UID 部署。
本文件不作为整条 Rust 备份链已运行的证明。

## 授权与事件

`BackupAuditPort` 只接受 `BackupAdmission` 能力，不再接收自由组合的账本、作业键和
目标。准入使用实际启动保留的 `SqliteAuditLedger`，请求声明的键不能代替批准。
端口只接受这一作业，不提供
通用审计追加、任意 action、正文、主体标签、全账本查询或自定义过滤器。

可信协调器先将原作业 Intent 持久化，再冻结和封存；释放全部冻结屏障后，
`BackupAdmission::approve` 才能从真正的 `SealedCheckpoint` 取得摘要、内容截止、
原保留期限及人侧审计链截止点。它从实际原账本核完整 Intent，并核截止 offset 上
真实记录的完整性哈希，要求 Intent 已包含在封存链中。准入是同账本中一条固定
`backup.snapshot` Intent，事件 ID 由 checkpoint ID 摘要生成，完整载荷绑定原键、
目标及上述事实；同 checkpoint 换 sequence、目标、来源或期限会触发幂等冲突。
准入必须在封存截止点之后落账、回执核对通过且仍未到期，才能返还能力。

重启 `resume` 只读核验原准入、原 Intent 和原链截止点，缺失/损坏不自动补造。
每次 dispatch 在原完整操作许可下重新核验准入。过期后仍允许按原键查询、远端
核对和补审计；再次交付正文必须额外通过 `check_live`，不得用恢复审计的权限重开
已过期正文。worker 的封闭事件映射不接受准入事件，不能自行签发授权。准入记录
不另建数据库或 JSON 文件，也不从路径猜来源标签。全服务调度和断线交付仍待接线。

`BackupAuditRequest` 只有 Append、Read 和 Admission 三种命令。Append 根据固定事件映射
重新生成完整事件，再逐字段比较 action、event ID、阶段、主体和载荷；未知字段、
额外正文、错键、假完整性标志、短快照 ID、同一数据/最终快照或倒置时间均拒绝。
Read 只能选择这一作业的 Intent 或 Outcome。成功消息是 worker 对既有远端事实
的陈述，本协议自身不构成远端核验证据，也不推进界面成功指针。

Admission 只读取这一原作业的持久准入回执，不接受调用方传入路径、seal、期限或
任意过滤器，也不写任何新记录。响应沿用同一 16 KiB 规范消息/请求摘要绑定/真实
peer 连接；客户端要求非空原回执、完整事件形状、回执哈希、相同 JobKey/目标和
准入晚于封存截止点，随后取得固定 `AdmissionFact`。这个 DTO 只表明事实自洽，
自身不是生产者的准入能力。`WorkerAuditClient::admitted_source` 通过原固定 socket
取得它；来源执行器仍须重开原固定根并核原期限。过期后可取非正文准入事实以续办
远端核对，不能把这种读取当作恢复正文权限。

写 Outcome 前，生产者在原账本中读取同一作业的 Intent，核对完整原事件及其目标。
查询只取该键/阶段、上限两条并要求至多一条；返回原回执的时间、offset 与哈希。
整个查前提/追加/回执构造持有原账本的完整操作许可，与 checkpoint 排空共用门禁。
重复事件返回原回执，不生成新的时间或 offset；同键不同内容仍由账本拒绝。

## 字节与连接

请求和响应各最多 16 KiB，编码过程即限额。只接受规范 JSON，拒绝未知或重复字段、
尾随内容与替代编码。响应绑定原请求字节的 SHA-256；客户端再核完整原事件、阶段
及回执哈希。Append 不接受空回执，Read 的空回执只表示本次查询未找到这一阶段。

`AuditSocket` 只消费已经连接的 Linux AF_UNIX/SOCK_STREAM，不打开路径或监听。
每次操作核真实内核 peer UID；批准值必须由启动配置提供。生产者的连接入口进一步
拒绝与 App 共用 UID 的 worker，root 和无效 UID 同样不被接受。

每个方向只传一个四字节大端长度头和有限正文，发送后半关闭写端。接收方必须看到
EOF 才交给业务层，额外一个字节即拒绝，因此多帧和流水线不会绕过单作业限制。
长度在分配前校验。所有非阻塞读写及 poll 共用原单调截止时间，最长十秒；短读、
重试和等待 EOF 都不重置预算。失败连接不可重用，也不自动重连重放。

客户端失去回执不能推断账本未写。续办只能保留原作业和原消息，重新查询或精确
重放；不能换键来规避未知结果。

`WorkerAuditClient` 仅从固定 root 配置取得 socket、生产者 UID 和专用组。逐级从
`/` 以 nofollow 原 FD 固定全部祖先，只允许 root/生产者可写且无扩展 ACL；直属父
目录必须是生产者/专用组 0750，socket 必须是同一身份 0660、单链接且无 ACL。
原 FD 保留至客户端销毁，连接前后及收回执后重开核对每级 inode、所有者和权限。
连接使用 AF_UNIX/SOCK_STREAM、NONBLOCK/CLOEXEC，队列满直接失败，不无界等待
或自动重试。每次核当前进程还是配置中的 worker，随后再次核实际 producer peer。

客户端实现 AuditLedger 接缝，但不持有真实或内存账本，不允许取得假完整操作许可。
追加先经封闭事件验证；query 只接受原键、明确阶段、limit=1 且没有其他选择条件。
实际监听生命周期、并发限额及完整服务调度仍是后续接线的一部分。

## 验证范围

定向测试覆盖固定消息/回执、真实 SQLite 精确幂等与重开、缺失或错配 Intent、
跨作业查询拒绝、原完整操作门禁、真实 UDS peer 拒绝、越界/截断/额外帧、无 EOF、
缓慢逐字节输入及持久追加后 ACK 丢失。传输正向夹具使用同 UID 的 socket pair，
生产连接入口另测拒绝同 UID；不得将这种夹具称为生产双 UID 正向验收。
原生路径测试另覆盖父目录/socket 换根、链接、非 socket、权限和扩展 ACL；其正向
路径夹具从私有根 FD 开始，生产入口始终从 `/` 开始，两者证据范围不能混淆。
准入交付另验原持久回执精确回传且不修改任何记录/期限、异键/异目标/普通 Intent
不能充当准入、损坏回执拒绝及真实有界 UDS 帧往返。

准入契约另覆盖缺失/部分记录、错误 schema/键/目标/摘要/期限/原链截止点、重开不
写入、过期只可补审计及 worker 无权创建准入。实际六 owner、双 Audit、Bridge
明确未装配的集成夹具完成封存后释放原屏障，再批准、精确重放、恢复并读取原事件；
另一真实审计库即使有同名 Intent，也不能认领该封存。夹具里的 Full 来源均是显式
批准的虚构数据，此测试不证明生产来源标签提供方或生产全链已完成。
