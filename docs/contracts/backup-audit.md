# 独立备份作业的审计通信

T-204，2026-11-13。已实现封闭消息、单作业生产者端口及已连接 Linux UDS 的帧传输；
尚未接入常驻 worker、固定路径监听器、持久作业准入或生产双 UID 部署。
本文件不作为整条 Rust 备份链已运行的证明。

## 授权与事件

`BackupAuditPort` 持有实际启动保留的 `SqliteAuditLedger`、可信协调器已批准的
`JobKey` 及目标类别。请求声明的键不能代替批准。端口只接受这一作业，不提供
通用审计追加、任意 action、正文、主体标签、全账本查询或自定义过滤器。

`BackupAuditRequest` 只有 Append 和 Read 两种命令。Append 根据固定事件映射
重新生成完整事件，再逐字段比较 action、event ID、阶段、主体和载荷；未知字段、
额外正文、错键、假完整性标志、短快照 ID、同一数据/最终快照或倒置时间均拒绝。
Read 只能选择这一作业的 Intent 或 Outcome。成功消息是 worker 对既有远端事实
的陈述，本协议自身不构成远端核验证据，也不推进界面成功指针。

写 Outcome 前，生产者在原账本中读取同一作业的 Intent，核对完整原事件及其目标。
查询只取该键/阶段、上限两条并要求至多一条；返回原回执的时间、offset 与哈希。
整个查前提/追加/回执构造持有原账本的完整操作许可，与 checkpoint 排空共用门禁。
重复事件返回原回执，不生成新的时间或 offset；同键不同内容仍由账本拒绝。

## 字节与连接

请求和响应各最多 16 KiB，编码过程即限额。只接受规范 JSON，拒绝未知或重复字段、
尾随内容与替代编码。响应绑定原请求字节的 SHA-256；客户端再核完整原事件、阶段
及回执哈希。Append 不接受空回执，Read 的空回执只表示本次查询未找到这一阶段。

`AuditSocket` 只消费已经连接的 Linux AF_UNIX/SOCK_STREAM，不打开路径或监听。
每次操作核真实内核 peer UID；批准值必须由启动配置提供。生产者的连接入口进一步
拒绝与 App 共用 UID 的 worker，root 和无效 UID 同样不被接受。

每个方向只传一个四字节大端长度头和有限正文，发送后半关闭写端。接收方必须看到
EOF 才交给业务层，额外一个字节即拒绝，因此多帧和流水线不会绕过单作业限制。
长度在分配前校验。所有非阻塞读写及 poll 共用原单调截止时间，最长十秒；短读、
重试和等待 EOF 都不重置预算。失败连接不可重用，也不自动重连重放。

客户端失去回执不能推断账本未写。续办只能保留原作业和原消息，重新查询或精确
重放；不能换键来规避未知结果。实际监听生命周期、套接字父目录的原身份验证、
独立 worker 客户端连接、并发限额及完整服务调度仍是后续接线的一部分。

## 验证范围

定向测试覆盖固定消息/回执、真实 SQLite 精确幂等与重开、缺失或错配 Intent、
跨作业查询拒绝、原完整操作门禁、真实 UDS peer 拒绝、越界/截断/额外帧、无 EOF、
缓慢逐字节输入及持久追加后 ACK 丢失。传输正向夹具使用同 UID 的 socket pair，
生产连接入口另测拒绝同 UID；不得将这种夹具称为生产双 UID 正向验收。
