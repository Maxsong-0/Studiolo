状态：2026-09-05，T-013 基础与T-014 v2保留/迁移均已通过双平台契约验收。
当前 v2 补充规则见 [安全回收与迁移](auth-retention.md)；历史T-013结果与本轮验证分开记录。
T-018新增已登记签发/CSRF配对/当前会话吊销，见[HTTP补充](auth-http.md)；旧Interface语义保持，尚未实际部署。
代码、双库故障与身份封装的实际验证范围见 [M2 验证记录](../m2/README.md)。
本片是可测试的持久会话基础，不是长期生产认证交付，不代表完整 M2 完成。

## 范围与可信入口

`studiolo-auth` 包含真实 Access 验证 Module 与独立会话 Module。
Access 配置由可信程序完整提供，不从请求、裸邮箱头或 Cookie 推导。
`AccessVerifier::verify(jwt)` 保留固定 HTTPS JWKS、RS256、issuer、audience、
邮箱、subject、时间等检查；`origin()` 只返回可信配置的公共来源。

`AccessIdentity` 的五个字段私有，只提供 `email()`、`subject()`、`issuer()`、
`audience()`、`expires_at()`；到期值为 UNIX 秒，audience 取已校验的配置值。
没有公开身份构造器、`Default` 或反序列化入口，不能用普通 JSON 伪造。
身份只能证明曾验证成功；每个 HTTP 请求仍须新验 JWT，不能缓存身份绕过入口。
T-013当时的 local-server 只替换依赖与导出；T-018另加显式会话组合入口，两个旧模式的来源保护、每请求验证和只读405仍保留。

非默认 `test-support` 仅导出无参数的固定虚构应用/邮箱配置与公钥验证器，
subject 沿用真实合法性规则；没有通用 JWKS/主体工厂，不含签名私钥。
签名夹具及可调整测试身份仅在测试编译中存在，不进入该 feature。
发布构建显式启用 `studiolo-auth/production`；与 `test-support` 同时启用时
由编译器报 `STUDIOLO_AUTH_TEST_FIXTURE_FORBIDDEN_IN_PRODUCTION`。
生产成功、特征混用指定错误及三项身份构造 compile-fail 已由主线实际验证。

## 最小 Interface

所有依赖由可信程序装配；HTTP 与调用者不持有 SQLite 连接。

| 调用 | 契约 |
|---|---|
| `open(root, config, audit, clock, random)` | 打开已批准的私有目录与主人绑定；不创建目录、不登记远端主人 |
| `migrate_v1(root, config, audit, clock, random)` | 显式验证并升级旧格式；v2幂等打开，保留旧活跃凭证 |
| `issue(identity)` | 校验身份并完成跨库授予流程；仅成功的原调用返回一次凭证 |
| `issue_enrolled(identity)` | 主人/已确认登记门槛后一次有界维护，后续签发事务均重验；旧issue不维护 |
| `check(identity, token)` | 重新检查读取会话并持久更新活动时间；只适用于普通读取 |
| `check_with_csrf(identity, token, csrf)` | 同事务验证双秘密配对；仍仅读取检查，不回送DB不存在的原CSRF |
| `sessions(identity, token)` | 经有效读取会话返回非秘密元信息，不返回令牌或摘要 |
| `revoke(identity, token, csrf, target)` | 经有效主人会话及其 CSRF 吊销指定会话 |
| `revoke_current(identity, token, csrf)` | 同事务取当前授权行并沿原逻辑吊销，不暴露半授权目标查询 |
| `revoke_all(identity, token, csrf)` | 同事务全部吊销并推进持久身份版本 |
| `flush_audit(max_events)` | 可信维护调用顺序补记 1～256 条原事件，不重新授权或吊销 |
| `maintain_retention()` | 最多16个已终态与16个epoch前缀；确认原回执/稳定许可后清理本地副本 |

`check` 没有内容 mutation 授权语义，不能把其返回值当作写权限。
元信息同样不能缓存为后续请求的授权证明。未知或已吊销的令牌不会自动换发。
`OwnerBinding` 是显式非秘密配置，不是签名身份，也不是本地来源授权证明。
重开时主人绑定及 TTL 必须与磁盘配置一致，不会自动改绑或静默迁移。

## 凭证、期限与状态

- v2 会话与 CSRF 各从独立256位安全随机种子派生，交付带用途/版本/持久序号的规范编码；旧64hex继续验证，具体HKDF与迁移拒重规则见补充契约。
  数据库只存域分离的 SHA-256 摘要，比较使用常量时间字节检查；不承诺数据库查询恒时。
- 会话公开 ID 为旧128位随机标识或v2持久签发序号，不是凭证或其摘要。
  秘密类型不实现 `Clone` 或 `Serialize`，`Debug` 脱敏，持有缓冲区释放时零化。
  显式暴露方法仅供受信任传输层；不保证调用方复制或记录后的秘密仍受保护。
- TTL 必须显式指定，满足 `0 < idle <= absolute <= 7 天`。
  预检时绝对期限取策略期限与首次 Access 到期的较早值，后续活动或新 JWT 不延长它。
  idle 从最终激活及后续成功读取的活动时间起算；审计等待不消耗尚未激活的 idle，
  但始终消耗绝对期限。pending 只按绝对期限失效，不能借此延长原始绝对期限。
  idle 30 分钟、absolute 12 小时只是运维建议，尚未作为真实部署配置启用。
- `now >= deadline` 即失效；当前 Access 到期、主人四字段、持久身份版本也须通过。
  活跃状态之外均不可认证；活跃会话到期变 `expired`，待激活会话过绝对期限变 `abandoned`。
- 持久 `clock_floor` 记录已观察时间。低于该值、负值或无法取得有效时间时拒绝，
  不能简单取较大时间继续授权。正常拒绝分支也提交时间地板、失效状态及拒绝计数。
  Auth 提交失败不返回授权；重新打开不会清空地板或复活已失效会话。

## 授予与跨库崩溃窗口

AuthDB 与 AuditLedger 没有共同事务。新会话流程为：

1. 检查真实身份、时间、版本与容量，持久预留不复用的签发序号；生成派生秘密并检查种子跨域拒重。序号耗尽也提交本轮到期状态、时间地板与容量拒绝计数。
2. 追加 Audit Intent 并验证回执；失败时不产生可用凭证。
3. 再检查身份、版本、期限、维护高水位与随机冲突，同一 Auth 事务写 `pending`、种子摘要和不可变 Outcome outbox。
4. 在 Auth 写事务之外补记 Outcome，核对原事件与回执，再持久确认。
5. 只有仍持有本次秘密的原签发调用，重新检查状态、摘要、版本、期限与审计回执，
   才能以 CAS 把自己的 `pending` 激活并落 `activated_at`；提交成功后返回凭证。

Outcome 表达“授权决定允许，凭证尚未发布”，不是客户端已经收到凭证。
失败可以留下孤立 Intent 或不可用的 pending，不能因此重建原秘密或重新授权。
多实例打开不能判断另一签发者是否崩溃，因此不会无条件废弃所有 pending；
补记者、重开和恢复流程均不激活它们，过绝对期限后标为 abandoned。
数据库激活提交与未来 HTTP 交付无法原子化；提交后崩溃可能留下未交付的孤儿会话，
允许它自行失效，不承诺“每次失败均无 active 行”或凭证恰好交付一次。

## 吊销、审计与有界存储

吊销先在 Auth 事务内失效目标并写不可变事件，再在事务外尽力补记。
Audit 不可用不撤销已提交的吊销；Auth 提交失败则不能报告成功。
全部吊销推进版本，阻止旧签发者迟到激活。指定目标不存在或已失效返回零，
不重复新增吊销事件；调用者自身仍必须持有有效身份、会话与 CSRF。
自我吊销后旧凭证不能再次作为有效调用身份，不承诺它可无限重试成功。

补记按原序列重放原始事件；审计追加成功后才确认回执，不重建时间或正文。
确认失败保留原事件，下一次重放利用 AuditLedger 稳定事件身份收敛。
普通有效读取不调用外部审计；失效及拒绝记录仍由 Auth 持久保存。
审计载荷从封闭字段构建，不包含 JWT、会话、CSRF、原始请求或凭证摘要。

首次创建生成并持久保存独立 128 位 `store_id`，重开沿用，不重新消耗随机值。
issue、revoke、expire、denied 事件均带该命名空间，避免独立 Auth 库共用
AuditLedger 时事件身份串库。跨库重放、关联校验及迟到拒绝快照确认已有通过的回归。
它不是密钥、远端防回滚证明，也不是复制数据库后可并行使用的凭证隔离机制。
每次事务核对会话与原 grant、精确回执、激活标记、吊销/失效事件、身份版本及时间地板；
不能仅把已吊销行的 state 翻回 active 就恢复权限。拒绝快照的桶、through 与载荷须一致。
`AuditRecord::verify_integrity` 由审计 Module 统一实现记录自洽检查；不证明记录来自
权威库、不验证前后邻居，也不防管理员一致重写全部数据。Auth 不另写一套哈希编码。

- **1024 是所有状态尚未回收会话的上限，不是同时在线上限。** 不隐式删除历史；仅受信任维护入口在原证据精确确认后回收已终态副本。饱和后新 `issue` 返回 `Capacity`。
  现有有效会话的合法吊销仍可执行，已通过饱和容量与审计不可用组合契约。
- 非拒绝类安全事件最多保留8192条，已送达但未回收记录也计入；单个事件或回执最多8192字节。固定一个维护计划与替换检查点使用独立槽位，不占安全事件预算。
- 拒绝按 8 个封闭原因分别累计，每个原因最多一个不可变待交付快照。
  确认后才推进已交付计数，再为后续增量安排快照；拒绝洪泛不能占满安全事件分区。
- v2 已实现有界回收与显式迁移；运行验收和生产维护调度状态见补充契约。实际HTTP、真实身份和完整M2发布门禁仍未通过。

## 私有存储保证与局限

Auth 独占固定 `auth.sqlite3`，不使用 TaskEngine-owned ControlDb 或 Audit 的连接。
目录必须预先存在、绝对路径、0700；路径各段不能是符号链接。
数据库及 `-wal`、`-shm`、`-journal` 必须为同目录主人拥有的 0600 普通文件，
不接受符号链接、硬链接或特殊节点。已有空库、未知格式/配置拒绝，不修权限或重建。
运行中复核目录和数据库对象身份；SQLite 使用 WAL/FULL、固定 schema 与事务校验。
事务验证会扫描保留的会话及事件，工作量随有界保留历史增长，不承诺恒定耗时；
完整历史在权威审计中持续增长，SQLite文件/WAL高水位不随逻辑回收自动缩小。

这些保证依赖可信、稳定父目录、本地文件系统锁与受信任程序装配；不是同 UID
进程或管理员隔离，不是任意替换竞态下的系统级沙箱，也不是数据库加密。
权限和时间地板不能发现管理员整体回滚旧数据库。非 Unix 平台失败关闭。
目录与备份生命周期、实际主人登记、秘密备份/恢复仍需独立设计与真实验收。

## 尚未交付与验证界限

本片没有会话 HTTP、Cookie 设置、Origin/Fetch Metadata/CSRF 的写请求组合入口，
没有首次登记 CLI、TOTP、L3、恢复码或内容写权限；远端登录不能抢注主人。
未来 HTTP 接线必须另建新鲜 JWT、有效会话、精确同源、会话 CSRF 和动作等级检查链。
不读写真实 Vault，不触真实凭据，不迁移或部署服务器，不替代设备和恢复演练。

T-013历史已通过：真实签名 Access 与旧 HTTP 回归、三项身份构造 compile-fail、生产特征正反检查，
私有文件负测、双期限/回退/重启、并发吊销/迟到激活、随机冲突/失败、命名空间与精确回执、
累计容量/拒绝聚合、秘密不泄漏、真实双 SQLite 审计故障及重放。Auth 共58项运行时契约。
故障覆盖真实 SQLite FULL/忙锁、query_only 写失败，以及激活前存储权限检查失败；
不把这些模拟当作真实 commit I/O、断电、管理员隔离或恢复演练。没有新前端/浏览器验收，
没有服务器 x86_64 原生验证、真实公网身份、NAS 或两周同步试跑，也未提交合并部署。

T-014 当前Auth94项运行时（14Access、15私有存储、65会话）与3项身份compile-fail；全workspace及生产隔离检查结果见补充契约。本片解决内部安全回收，未接线生产后台调度或新增HTTP/TOTP。
