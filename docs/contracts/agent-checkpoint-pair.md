# 身份库与独立审计链的封存能力

`AgentIdentityView::checkpoint_assembly` 从实际身份库取得固定源，并只打开同一已批准根下的 `audit/audit.sqlite3`。返回能力没有身份写入、审计追加、初始化或任意路径接口；目录或账本缺失即失败，不创建空库。原身份库或审计库替换后不能悄悄重新绑定。

`AuditCheckpointAccess` 将同一实际账本的完整操作排空与 SQLite 冻结封装在一起。人侧用正在服务的原 ledger；独立接入方服务使用固定原根和共享跨进程门禁。协调顺序为先排空接入方，再排空人侧；身份库在七 owner 的 AgentStore 位置冻结，附属账本仍等最后 Audit 阶段冻结。两条链各自记录截止点，不能比较或互换同名 offset。封存窗口只定格之后（BUG-045，2026-11-22），身份库与两本账本都在冻结窗口放开之后、从各自定格的读事务里核回执和导出；身份库的排空（没有未结束的降级窗口）与逐行校验也在放开之后在定格上做（`FrozenAgentStore::validate`）；身份库的读取派生索引核对读的是定格的身份库和定格的接入方账本。
