# 账户内因子操作（T-025）

本契约续接[浏览器会话](frontend-session.md)、[因子HTTP](auth-factor-http.md)和
[只读状态](auth-factor-state.md)。实现与实测范围以M2验证记录为准。

## 能力和生命周期

账户弹层通过固定L2状态GET发现因子能力。明确`factors:null`表示未启用；404、网络错误
或不规范JSON表示未知，只关闭因子操作，不推断旧模式或降低会话授权。bootstrap和session
形状保持，不能试发POST探测能力。

`SessionClient`拥有唯一CSRF、请求代次和POST互斥；封闭因子动作复用这些能力，不另建可
绕过会话失效处理的客户端。近期认证只是显示信息，时间到期和操作授权最终由服务器检查。
pending只作提示，不能永久禁止显式新操作，因为既有动作会按原规则清理可释放的过期决定。

所有OTP/恢复码输入提交即清空。弹层关闭、页面隐藏或会话变化时清除输入、已展示原码
与对应应用引用，拒绝迟到响应。JavaScript不能承诺浏览器字符串、传输缓冲或剪贴板零化。

## 三条明确操作

- 二次认证：只发六位OTP；成功显示认证期限，不生成客户端授权凭据。
- 恢复码换发：明确告知整批旧码失效，用户点击才POST空对象；严格验证十个规范原码后
  仅在当前弹层交付。复制由用户明确点击；关闭后不能GET重读。
- 恢复验证器：只发恢复码和预配置新验证器的OTP，不接收种子、任意引用或路径。
  明确204空成功响应后清内容、广播全旧会话失效；重新登录仍由用户点击。

204必须使用专门的空响应解码，不能把成功恢复当成JSON解析失败。其他成功响应继续
严格校验形状；无法理解的成功响应按结果不确定处理，不自行补发。

## 错误与结果不确定

401沿会话入口关闭内容并核对；403/409清秘密输入，保留Cookie，提供显式状态核对。
不解析中文错误文本猜内部错误码。429表示限频，没有服务端时间就不猜倒计时。
503、断网、取消或异常成功响应可能已经提交，只允许显式GET核对，不自动重放POST。

状态查询只显示当时事实，pending=false或值未变化不能确认原操作失败。若恢复码响应
丢失，明确原码无法重读，核对状态也无法确认换发结果；用户若再次生成，必须作为新的
明确操作接受旧批次失效，而不是把它包装成“重试”。

界面延续现有账户弹层、图标、按压反馈、键盘焦点和可中断动效；窄屏、减少动效及
关闭时秘密清理须实际验证。虚构浏览器夹具不替代真实Access、HTTPS Cookie或手机配对。
