# Auth v4：恢复码与实际因子替换

状态：2026-09-05 T-016双平台契约验收完成，macOS421/Linux429及规范/生产正反检查通过，本片新增44项。补充[会话](auth-session.md)、
[安全保留](auth-retention.md)与[TOTP](auth-totp.md)，不代表真实秘密装配、HTTP或生产已接线。
授权等级与失败语义以项目档案《敏感动作枚举表》T-016裁决为准。

## 小 Interface 与可信装配

- `SessionManager::migrate_v3(...)`：显式验证v3并同事务增量升级v4；已有v4幂等。
  新目录依次建立v2/v3/v4；已有v1/v2须先走以前的迁移接口。普通fresh/open仍不自动升级旧库。
- `Recovery::attach(Arc<SessionManager>)`：只接受v4，不生成秘密或登记因子。
- `PreparedTotpFactor::prepare(sessions, seed)`：可信装配先安全保存并交付新种子，再绑定原库/原登记。
  拒绝同引用、在新引用下复用当前原种子；不读取文件、不接受路径或网络反序列化。
- `Recovery::rotate_codes(request)`：新鲜Access、L2、CSRF及当前真实L3，成功后一次性交付十枚新码。
- `Recovery::replace_factor(request, code, prepared, otp)`：同样要求新鲜Access、L2、CSRF，
  一枚当前未用恢复码加预先准备的新因子正确OTP，真实切换因子并吊销全部旧会话。
  不要求旧手机OTP，不返回恢复Cookie、通用L3或干净机恢复身份。
- `Recovery::flush_audit()`：仅补记当前两个事件及重确认必要原证明；最多返回2个新增ACK，绝不激活。

成功替换返回的新`Totp`只是运行句柄。包括当前调用会话在内的全部旧会话均失效；
必须重新登录和用更新的OTP时间步提权，不能凭返回值调用敏感操作。
可信准备对象是进程内职责边界，不是OS隔离；未来HTTP只能取得受限运行接口，不能持有秘密装配权。

## 秘密和猜码预算

恢复码规范编码为`r1.<16位小写十六进制正批号>.<2位槽号>.<32位秘密>`，固定55个ASCII字节。
槽号00～09；每码独立取得32字节CSPRNG输入，经HKDF-SHA256派生128位秘密。
salt为`studiolo-recovery-v1\0`，info为16字节库ID、8字节大端批号、1字节槽号。
只保存绑定库ID的SHA256码摘要；原输入与已保留会话/固定legacy凭证作原域碰撞检查。
批内重复随机输入失败关闭；跨批序号域分离防旧码复活，不承诺在随机源失陷后仍安全。

`RecoveryCode`/`RecoveryCodes`无Clone、Serialize、Display，Debug脱敏，拥有的原码缓冲区释放时零化。
`expose_secret`只服务可信交付；调用者自行复制的字符串不受此保证覆盖。审计不含码、摘要、种子或引用。

恢复验证独立采用账号/可信来源各5次受理/900000毫秒；先提交预算再检查码或OTP，成功不退款。
更换Cookie、来源、重启不能重置账号预算。最多64网络桶，另加account/local；不驱逐活跃桶。
格式错误在解析面拒绝。换发已受L3保护，不扣恢复猜码预算。
共享限流实现保留原TOTP表、哈希域和语义，两类验证不共享额度。

## 两个完整动作与失败边界

换发先独立保留操作序号，再于锁外生成秘密，重验后持久暂存十枚摘要与唯一pending。
生成期间已有更新操作取得序号时，旧调用拒绝倒序发布；失败烧号，不复用。
双审计ACK后仅原调用重验当前L3、身份/会话/CSRF、原因子与期限，才原子替换整批旧码并返回新原码。
失败不从数据库重读原码；提交与客户端实际收到响应无法原子保证，可能留下未收到的新批次。

恢复先持久扣预算，确认当前码和新OTP都正确后，同事务烧掉码及候选OTP，并固定唯一恢复决定。
旧因子在此时不改变。审计双确认之后，原调用再次验权；在一次Auth事务中推进epoch、吊销全部会话、
插入原有撤权outbox、真实替换因子、清空所有L3、废止整批旧码、清pending并完整校验。
提交前失败回滚整次切换；先前已烧的码不会恢复。提交后存储复核报错或响应丢失时，切换和吊销可能已经生效；
应修复外部条件后重开核对权威状态，不能自动重放原操作。迁移同样可能提交后报错、实际已合法v4，可幂等重开。
撤权outbox补记失败不撤销已成功替换；本片未做真实commit I/O或断电注入。

pending窗口为消费时起300000毫秒，受原会话absolute与本次Access期限封顶；受理到消费也限5分钟。
无10分钟恢复Cookie。审计等待占用窗口，不续期；到期或被吊销的调用不能因迟到回执重新激活。
TOTP与Recovery pending双向互斥，普通L2安全吊销不受阻塞。
只有双ACK的失效pending可清理；未确认pending保留其依赖会话，阻止回收丢证据。

候选OTP保留一个独立永久高水位及消费Operation锚点；失败清理/换发/删批均不清空。
普通TOTP也比较该高水位，保守地跨因子使用，可能需等下一30秒步，不承诺换因子即时验同一步。
只拒绝复用当前原种子，不跟踪所有历史原种子；可信装配仍必须为每次替换生成全新秘密。

## 有界存储与精确审计

v4只追加四张STRICT表、六个对象，完整schema31对象，原v1/v2/v3 DDL不变：

| 表 | 逻辑预算 |
|---|---|
| `recovery_control` | 1行：单调序号、当前码批/最近替换双证明、候选高水位锚点、已用位图 |
| `recovery_codes` | 当前10枚＋暂存10枚，最多20行；已消费码附原决定与双ACK |
| `recovery_pending` | 全主人最多1个不可变决定，恢复消费ACK与码行精确镜像 |
| `recovery_rates` | 最多66行，不存原始来源地址 |

Operation≤4096字节、Proof≤65536字节、单回执≤8192字节；先检查原始长度/数量再解析规范JSON。
位图、摘要、批/槽、序号、时间、原因子、新登记和双回执均交叉校验；未知字段或简单单列回退拒绝。
恢复目标的`totp.recovered`原事件同时作为新因子登记证明，原有TOTP事件和JSON编码保持兼容。

交付前精确重确认当前批、最近替换、旧消费码、原登记及将被替换L3的原回执；按事件ID与phase去重。
替换最多涉及1024份旧L3，单次证明交付阶段预算2076（含当前2）；换发最多30。成功替换后另有最多256条会话outbox补记，
不是整个公开替换调用最多2076次。全部Audit调用在Auth锁外。
另一审计历史、自洽但非原字节回执、反向offset或迟到错配ACK不能推进状态。
外部坏回执返回AuditUnavailable；Auth可写时仍提交观察到的时间地板/到期及拒绝计数，不能因拒绝后时钟回退复活旧权限。
真实本地损坏仍为CorruptStore；不为了补记绕过完整校验。
逻辑数量有界不代表固定墙钟耗时、WAL大小或审计历史不增长；满表慢审计仍可能超过5分钟而失败关闭。

## 尚未交付的生产门槛

真实TTY、secret mount、二维码、离线恢复码保管/安全通知、Cookie/Origin/代理HTTP、真实主人登记，
以及无手机无恢复码的可信本地恢复、干净机restore身份仍需单独实现和验收。
不抵御管理员一致重写、Auth整库回滚/克隆双写、真实TOTP钓鱼；不冒称NIST认证或断电/commit I/O实验。
没有邮件移除TOTP、清库重登或默认恢复成功入口。
