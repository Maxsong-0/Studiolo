# Broker 封存与新根恢复

T-204，2026-11-13。本文描述实际 Broker 存储机制；完整七方协调器、真实 Audit
回调、inclusion plan、独立 Worker 和启动装配仍须在组合根接齐，不能据此宣称
灾难备份或生产恢复验收已完成。

`FsVaultBroker::freeze_checkpoint` 移入原实例，保留原 canonical 写租约。冻结句柄
不导出普通读写接口；`thaw` 在任意失败之后都返还原实例，既不重开第二写者，也不
回滚或清理活动根。Prepared 可读仍视为未排空；永久写者状态和正文 outbox 必须空闲。

核对由两端完成：Broker 从固定存储重建原事件；可信组合根用 FrozenAudit 核对
完整事件、原 offset 和 hash。Broker 不依赖 Audit crate，也不允许公开 DTO 顶替
自己的永久记录。核对覆盖正文永久双 ACK、文件操作请求/终态/双 ACK，以及最后
保留的维护槽。还从幂等终态反查母本，整个请求目录被删掉也不能冒充无审计历史。

核对前后分别扫描 canonical 和 writer-data 的完整树；导出必须与这一组摘要相同。
摘要覆盖文件名、目录结构、空目录、文件长度与全部正文。256 KiB 流式缓冲、两根
合计 100 万节点/512 GiB、64 级深度、目标预留 2 GiB 和原始截止时刻限制全部适用。
拒绝链接、特殊节点、跨设备、非本用户节点和源身份漂移。

两个目标必须预先批准、0700、为空，且与源及彼此在路径和物理祖先上均不重叠。
只创建 0600 独立文件和 0700 目录；文件与父目录同步后逐项重开，再复核完整目标
摘要和原源摘要。没有硬链接、覆盖现有目标或递归清理。失败残片不能作为恢复点。
本机制的全量物化不能替代组合根先行完成的逐对象 inclusion plan 和最终原子封存。

封存保留原绑定字节。新目录恢复必须由 Broker `rebind_new_roots` 完成：保留 Vault
UUID/pair_id，重绑两个主根、已启用 history/meta-v1、maintenance-v1 和文件操作
目录/删除隔离区。空历史只在写者水位未前进、无操作/终态且目录确实为空时记录为
未启用。缺失已启用存储、半初始化或逻辑配对不符均拒绝。

原审计事件、幂等键、墓碑内容摘要和历史内容证明不改写。删除对象可以在新根上
重新核验历史字节并执行真正的墓碑恢复。lineage 尚为 Rebinding 时，普通打开和
初始化都拒绝，即使两个主 binding 已写完；只有显式恢复接手可继续。

## 实际工作台与 Audit 接线

`CanonicalWorkbench::freeze_checkpoint` 移走正在服务的 Broker；任何失败或上层展开均返还同一个 owner。普通写者槽在窗口内为空，原唯一租约仍被持有，既不重开写者也不释放给第二进程。

`FrozenWorkbench::verify_audit` 复用线上正文、类型化文件操作和维护三个事件映射，按永久 ACK 的原 offset 读取真实 FrozenAudit，再核对完整事件和原记录哈希。相同 event_id 但 action/payload 不符，或只持有真实 offset 而哈希不符，都拒绝导出。没有新增第二套 payload 编码。
