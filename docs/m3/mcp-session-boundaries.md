# MCP 会话、凭据轮换和资源边界

T-046，2026-09-12。本文描述当前实现；本地契约与部署验收分别记录在
[整体收尾台账](../m2/m2-m3-closeout.md)，不代表线上已经更新。

## 身份连续性

每个 MCP 会话同时绑定首次握手的类型和凭据摘要。POST、GET/SSE、
Last-Event-ID 续读及 DELETE 都必须使用同一凭据；只知道会话 ID 不获得读取权。
类型撤销或凭据轮换后，旧会话和旧流失效，客户端必须重新 initialize。
每次供给仍核对原有 instance 身份和路径白名单。

流交付前重新核对身份与期限；后台每秒检查过期及已撤权的会话。
断开连接、取消 HTTP future 或删除会话，不等于后台供给作业已经结束。
只有实际创建结束且传输 worker 退出后才能回收对应容量；供给作业另持工作许可。

## 固定预算

| 对象 | 上限 |
| --- | --- |
| 全部会话（含预占与待清理） | 128 |
| 每个类型的会话 | 32 |
| 每分钟新建尝试 | 32；失败、取消不退还次数 |
| 同时活动传输 | 16 |
| 同时执行的实际供给 | 16 |
| initialize / 请求响应头等待 | 30 秒 |
| 空闲期限 | 15 分钟；成功供给才推进活动时间 |
| 绝对期限 | 1 小时 |

容量耗尽返回 429，带 Retry-After；存储或传输不能确认时拒绝继续。
这些边界不改变 agent 读取审计降级规则，也不向 agent 提供内容写入权。

## 断线与重试

仍在进行的流可在原会话、原凭据下重连。已经完成或取消的 POST 不保存历史事件
供后续重放；它们的旧 Last-Event-ID 返回空 SSE，不表示重新读取成功。
客户端需要再次执行只读工具以获得新结果与对应的新读取审计。

SDK 正常最终响应会立即删除通道。取消或资源注销的完成通道采用零保留时间，
在下一次事件循环处理前移除。契约分别连续验证正常完成和取消后的旧事件不可回放。
这不是持久消息队列，也不承诺断电后恢复 MCP 会话。
