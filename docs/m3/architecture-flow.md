# T-042 模块关系、数据流与设计任务路径

在 T-041 项目运作页面上增加有来源的结构化设计说明。所有节点、关系和步骤来自
同代 Markdown，目录存在性继续使用 T-041 仓库观测。依赖边是**文档声明依赖**，
不是扫描源码得到的实际依赖；步骤是**设计顺序**，不是当前任务、事件回放或执行器。

## 可选来源与格式

只读取已索引的 `项目/<项目名>/01-框架/项目运作.md`。文件是普通 Markdown，
不加入全局项目骨架；缺文件显示不可用。人写 Mermaid、SVG、HTML 和链接均不执行。
源文中的代码围栏、YAML frontmatter 和 HTML 注释不能生成章节或表格。

声明包含三个精确二级章节，每节一张表，列名和顺序如下。节点至少一个，关系和
任务路径可用只有表头/分隔行的空表明确表示暂无声明。重复章节、额外表、错误列、
悬空引用、重复 ID 或预算超限使整份架构声明无效，不发布部分图；T-041 目录图独立。
表格必须连续且每行保留首尾竖线；这些二级章节内不接受子标题。整段被注释的
伪表格会忽略，但可见表格行中会改写字段的 HTML 注释使声明无效。

```markdown
## 节点

| ID | 名称 | 类型 | 目录 | 职责 |
|---|---|---|---|---|
| query | 检索接口 | 接口 | src/search | 接收查询 |
| catalog | 资料索引 | 模块 | src/catalog | 组织资料 |

## 关系

| 起点 | 终点 | 类型 | 说明 |
|---|---|---|---|
| query | catalog | 依赖 | 查询资料索引 |
| catalog | query | 数据流 | 返回索引结果 |

## 任务路径

| 流程ID | 流程名称 | 步骤 | 节点ID | 说明 |
|---|---|---|---|---|
| search | 查询资料 | 1 | query | 接收条件 |
| search | 查询资料 | 2 | catalog | 检索资料 |
| search | 查询资料 | 3 | query | 返回结果 |
```

节点类型：`模块`、`接口`、`外部`、`数据`；JSON 分别为 `module`、`interface`、
`external`、`data`。关系类型只有 `依赖`/`数据流`，JSON 为 `dependency`/`data_flow`。
目录 `-` 表示无绑定，其他值必须是可见、规范的相对 VaultPath，无隐藏段、控制字符
或越界路径；这是可选目录关联，不能从它推断代码已实现。文本保留原义，作为普通
字符串转义；不以 Markdown 清洗改写 ID、路径或说明。

ID/流程 ID 为 `[a-z][a-z0-9_-]{0,47}`，区分的是明确 ID，不以名称猜同一节点。
节点 ID 唯一，关系起止点必须存在，同起点/终点/类型不得重复；循环和自环合法。
同流程 ID 的名称必须一致，步骤为连续的 `1..N`，按步骤排序；同一节点可以再次
出现，但同流程不得重复步骤。邻接步骤不自动生成依赖边或数据流边。

整文最多 64 KiB；最多 64 节点、128 关系、8 流程、每流程 32 步。名称/关系标签
最多 256 UTF-8 字节，职责/步骤说明最多 1024 字节，目录最多 1024 字节。预算在
扫描/插入时检查；空名称或空说明不能形成有效声明。

## 查询与证据

现有 `GET /api/project-operations?project=...&generation=N` 增加 `architecture`，
与目录声明取自同一个固定 generation，并沿用来源/会话门禁、查询信号量与取消后
阻塞许可管理。查询不接受宿主路径，不增加 FS/网络/执行能力。

```text
architecture: {
  status: ready | unavailable | invalid,
  source: SourceLocation | null,
  nodes: [{ id, label, kind, directory: string | null, description, source }],
  relations: [{ from, to, kind, label, source }],
  flows: [{ id, label, steps: [{ order, node, description, source }] }],
  diagnostics: string[]
}
```

每个节点、关系、步骤的 `source` 都是该文档的真实一基行号；顶层无文档时为 null。
`ready` 只表示完整声明可解释，不能当作实际架构核验通过。无效声明清空三类数据、
保留原因和原文入口；未绑定仓库也能看设计声明，目录证据保持未核验。

节点关联目录与已有 `drift` 路径精确匹配；未被 T-041 比较范围覆盖时明确未核验，
不为架构图扩大扫描层级。目录存在、缺失或未文档化独立展示；一个图不可用不使
另一类证据变成空结果或通过。旧服务缺少 `architecture` 字段时前端降级为不可用，
字段存在但损坏时报告响应错误，不能静默藏掉。

## 交互与验收

界面视觉以 [T-130 瑞士网格＋工程图纸规范](../design/t130-design-system.md) 为准（2026-09-23 起取代原 Apple 浅色界面）；仍用自有 DOM 图形、自然中文排版、来源弹窗与 reduced-motion。
关系按方向展示，可选模块并筛选声明依赖/数据流；设计路径支持选择流程、前一步/
后一步与直接选步骤。没有自动播放或后台执行。图形失败回退有来源的纯文本，不能
白屏；刷新/切换项目或代次不能保留上一份图或步骤状态。

虚构示例继续使用 [T-041 示例](../../examples/m3-project-operations/README.md)。
