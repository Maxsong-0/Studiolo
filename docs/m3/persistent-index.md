# 持久派生索引（T-039，2026-09-10）

依据 Vault ADR-015/016，为 M3 供给和后续图 2 复用同一套派生语义。
本片增加可选磁盘解析缓存，以及进程内未变读模型的共享；图 2 展示和结构漂移仍属后续。
索引保存派生结果，源 Markdown 和完整副本验证继续决定内容、可见路径与来源新鲜度。

## 运行路径

1. 每次托管副本请求先执行既有完整验证，生成本次 `Snapshot` 和 `Freshness`。
   直接 Vault 模式沿用首扫、每 60 秒重扫和管理端重扫，不改成每请求扫描。
2. 当前笔记集合与上一代完全相同时，共享上一代 `Arc<WorkbenchReadModel>`。
   新的代次、附件条目、回执及来源年龄仍来自本次扫描；没有以缓存命中短路验证。
3. 输入变化时，以逻辑路径、精确正文 SHA-256、字节数匹配单篇解析结果。
   未匹配者重新解析 YAML/Markdown，删除和重命名不会遗留可见路径。
4. 所有链接解析、反链、健康度和项目视图重新构建，避免新增目标、别名或就近候选变化后残留旧结论。
5. `WorkbenchReadModel` 的正文、搜索片段来自本次输入；MCP/HTTP 的正文、revision、目录和路牌继续从当前快照读取。
   类型鉴权、会话校验、吊销、读取审计与路牌预算沿用同一供给链。

`vault-index` 仅编码单篇 frontmatter、平面标题、未解析 Wikilink 及来源位置/上下文；
不持有文件系统能力，不保存 Markdown 全文、身份、凭据、回执或跨文档解析结论。
缓存仍含标题、frontmatter 和局部上下文等源资料，必须保存在私有目录。
`workbench` 继续用同一索引生成视图，没有第二套解析器。

## 显式启用与目录边界

在原 `serve` 参数后增加 `--index-cache /绝对/独立私有目录`。
目录须由操作者预建为 0700；服务只创建固定的 0600 `index.sqlite3`，不自动创建目录。
缓存根与 `--vault` 或 `--replica-root`、`--data` 必须彼此不包含；审计目录已包含在 data 中。
逐层拒绝符号链接和父目录跳转，并检查规范路径、大小写别名和文件身份。

```bash
# 在获准的实例上预建一个与源及 data 平级的目录。
install -d -m 700 /绝对/私有缓存目录
# 原 serve 命令末尾增加：
# --index-cache /绝对/私有缓存目录
```

未指定参数时没有磁盘缓存，仍可复用进程内解析和未变模型。
启动输出 `IndexStatus`，供本机验收：`source` 为 Rebuilt、Disk、Memory 或 Incremental，
`parsed` 为本次实际解析篇数，`reused` 为复用篇数；`persistence` 表示最近一次磁盘操作状态，
不代表每个请求都检查了磁盘缓存。诊断字段不扩充对外路牌或协议响应。

## 存储与失效

- 固定 SQLite application ID、schema 版本、唯一表、唯一缓存槽；拒绝其他版本或额外 schema 对象。
- 来源命名空间由源模式、绝对根路径和排序后的白名单摘要组成；更换范围不能命中旧槽。
- 编码包含独立的缓存格式版本与解析规则版本。修改 Markdown/YAML 语义时须递增 `PARSE_CACHE_VERSION`。
- 读写均检查根、库和 sidecar 的权限、属主、链接数、设备及已绑定 inode；SQLite 使用 NOFOLLOW。
- 单批最多 32 MiB、25,000 篇；读侧先查数据库长度和类型再分配负载，编码有硬上限。
- 单槽在事务内替换，失败保留上一批；DELETE journal 与 secure_delete 减少旧负载在库中的残留。
  这不是文件系统快照或物理磁盘擦除保证，也不是需要备份的权威库。
- 缓存为空、过期版本、解码失败或读写不可用时，重新使用已验证源构建；不能因此复用未验证来源。
  已知 SQLite 格式且字节摘要有效时，codec 失效可重建并替换；
  已有损坏/未知 SQLite 库保留原样，不删除或改写。
- 配置的缓存路径不安全或与源/身份目录重叠，启动拒绝；监听器尚未打开。
  运行期缓存失效不妨碍新鲜源的正常读取，模型仍可在内存派生。

SHA-256 绑定输入与检测意外损坏，不认证派生语义；私有目录是缓存的信任边界。
能以服务同一 UID 篡改缓存及摘要的进程已位于该边界内，本片不声称抵御它伪造派生元数据。
即使如此，缓存本身也不能增加白名单路径、恢复正文、授予身份权限或声明来源新鲜度。
