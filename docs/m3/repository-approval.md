# 图2生产仓库批准契约

T-046，2026-09-12。实现与本机契约已验证，真实生产配置和发布尚待验收。
目录、Cargo 清单和人工 Module/Interface 声明沿用图2现有查询及来源展示。

## 配置与装配

在既有主人私有 JSON 配置中，可选添加一个封闭对象：

```json
{
  "project_repository": {
    "version": 1,
    "project": "项目/示例工坊",
    "directory": "/srv/studiolo/repository",
    "cargo_dependencies": false
  }
}
```

这是配置片段，不能单独替代主人、Auth、Audit 等必填配置。省略对象表示不绑定；
显式 null、未知字段、非规范绝对目录或非 `项目/<名称>` 标识拒绝。每实例最多一个
项目，查询参数不能指定或改写宿主路径。Cargo 读取必须显式设为 true。

`Config::repository_serving_roots` 校验配置文件及其真实私有父目录、Vault、前端资源、
Auth/Audit、可选 writer data 和 Unix ingress 根。仓库与这些根必须隔离，不接受
嵌套、路径替换或链接绕过。批准对象没有公开构造器或反序列化入口；
`ProjectRepository::open_approved` 比较实际打开句柄身份后才接入会话组合。

这项配置不放宽旧 `--project-repository` 参数：它仍只适用于旧本机/Access只读组合，
会话、canonical 或因子模式仍拒绝该参数。库调用不能把旧未批准仓库接入会话模式，
也不能通过旧 builder 把配置中关闭的 Cargo 权限重新打开。

## 查询与失败语义

启动在双库、秘密装配和外部取钥之前先校验批准，监听前再复核；每次查询在读取和
发布前重验固定配置文件、各根身份及隔离关系。替换配置不是热更新授权，需要明确
重启后重新批准；配置或根漂移使本次仓库证据及观测时间全部不可用，不能保留旧
目录、Cargo 或源码结论当作新事实。人工声明和设计路径仍可按其索引代次显示。

实际目录内容变化仍按两轮有界完整观测检查；这是观测一致性，不是跨根文件系统
事务。身份、范围和根验证失败不得回退到旧 CLI 或自动查找其他仓库。

## 源码解析与秘密来源

批准模式只开放目录和明确批准的 Cargo 清单。Rust 源码 builder 在批准模式直接
拒绝：白名单和合作式预算不能替代第三方解析器的生产进程隔离。完整符号解析
并非本阶段新增前提；既有实验功能的历史证据见原 T-044/T-045 文档。

`seed_ref` 是逻辑秘密引用，不是目录。程序不能从环境值推断 EnvironmentFile 或
systemd credential 的来源路径，因此不添加虚构的 `seed_directory` 配置，也不宣称
已验证未知秘密来源。部署时必须实查实际秘密注入文件及其私有目录与仓库隔离，
不把私有文件复制进仓库或 Vault。

## 当前验证

配置与装配契约覆盖错误/缺失对象、权限及链接、配置/根替换、服务根嵌套、无秘密
装配前失败、旧 builder 不能扩权、源码拒绝和查询漂移清除；包含不可反序列化的
compile-fail。它们属于本机实现证据，不证明服务器当前已使用上述批准模式。
