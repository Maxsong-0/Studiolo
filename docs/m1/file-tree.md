# T-010 文件树与只读附件信息

文件树与搜索、原文属于同一不可变 generation。入口为「文档 → 文件树」，默认仍进入搜索。
此片只展示附件元信息，不提供内容读取、预览、上传或下载；完整 M1 仍未完成。

## 数据与安全边界

- `ReadOnlyVault::scan()` 一次受限遍历同时输出目录清单、Markdown 字节和附件元信息；
  `scan_markdown()` 保留为兼容 Interface，委托同一 Implementation。
- 空目录与纯附件目录均保留。隐藏组件仍排除，`.gitkeep` 不显示；并非完整系统文件浏览器。
- 所有普通文件都校验类型、链接数、设备与稳定性；附件在 Linux 用根句柄下的 O_PATH，
  macOS 用固定父目录句柄下不跟随链接的 stat，双次复核元信息，绝不读取内容。
  Markdown 仍受 UTF-8 和读取预算约束；不允许附件伪装成笔记参与搜索或原文。
- 碰撞、链接、特殊文件、不稳定读取等诊断使整代拒绝发布。刷新失败继续提供上一完整代次；
  不保证整个文件系统具备事务快照语义，也不承诺系统 atime 不变。
- 扫描预算：单笔记 4 MiB、总 Markdown 256 MiB、条目 50,000、深度 32、
  聚合逻辑路径 16 MiB；隐藏条目也计入枚举上限。附件大小不计入 Markdown 内容预算。
- 每目录枚举时建立名称碰撞索引，避免扫描每个文件时重复全目录查名；
  独立 `read_file` 继续执行完整路径防线，不借用过期扫描状态。
- `FileTree` 是 workbench 内纯 Deep Module，不依赖文件系统。构建时校验父目录、唯一路径、
  类型及 Markdown 路径/字节数一致性；为每目录建立子项索引，HTTP 查询不触碰源目录。

## HTTP Interface

`GET /api/tree?path=<URL编码的目录路径>&offset=0&generation=<代次>`。

- `path` 必填；空串表示根目录，其余为规范逻辑路径，不是宿主路径。
- `offset` 默认 0；每页最多 200 项，先目录后文件，各组按完整逻辑路径排序。
- 响应：`{generation,path,offset,total,entries,next_offset}`；终页 `next_offset` 为 null。
- 子项：`{path,name,kind,size_bytes,child_count}`。
  `kind` 为 `directory` / `markdown` / `attachment`。
  目录 `size_bytes=null`，`child_count` 为直接子项数；文件相反，大小是精确十进制字符串，
  避免 JavaScript 数字精度丢失。大小不等于 MIME 或内容安全认证。
- 400：无效路径、非目录、无效分页；404：目录不在此代；409：旧代；429：查询工作槽已满。
  复用搜索/原文的两个后台工作槽，取消请求不提前释放仍在执行的任务。
- 沿用全路由 Host、Origin、Fetch Metadata 及显式 Access 身份校验，无 CORS 或写方法豁免。
  附件不通过文档或静态资源路径暴露。

## 网页行为与验收

- 仅展开目录时请求子项；分页替换当前目录页而非无限追加，不静默截断。
- 目录有加载、失败重试、空态与过期刷新提示；代次改变后旧树和附件选择一并清空。
- Markdown 打开已有原文查看器第 1 行；附件仅展示完整路径、后缀说明、精确字节数。
  文件名与路径均转义，后缀不表示已验证 MIME；即使是 HTML/SVG 也不执行内容。
- 合成大目录用于验证分页边界，不等于真实 Vault 的吞吐或 10GB/50GB 容量验收。
