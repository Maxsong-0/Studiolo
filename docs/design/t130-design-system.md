## 1. 令牌（`web/src/styles/tokens.css` 单一来源）

所有样式只引用令牌；深浅色由 `tokens.css` 统一控制，禁止局部深色补丁。缺省跟随系统；T-199 起可在「更多」里手动选浅色或深色。系统深色与手动深色两段令牌须逐字相同，由测试守住；选择器用 `:where()`，不盖过后面的高对比度规则。

- **不再有**蓝色强调、渐变、毛玻璃、柔影。选中＝黑底反白；悬停＝`--paper-raised` 底。
- 状态不靠颜色单独表达：`■` 运行/正常（ink 实心）、`□` 进行中/待定（ink 空心）、红 `■` 故障/等你、灰虚线框 休眠。
- 阴影只有一种：浮层 `box-shadow: 10px 10px 0 var(--ink)`（硬偏移，无模糊）。
- 圆角一律 0，唯一例外是圈号（圆）。
- z 轴只用四档：`--z-sticky: 10`、`--z-popover: 20`、`--z-dialog: 30`、`--z-toast: 40`。

## 3. 网格语法

- 页面外边距 20px 28px 24px。顶栏 46px，底边 3px `--ink`。
- 内容区是 **12 列网格，格子之间 1px 黑线**：容器 `background: var(--ink); gap: 1px; border: 1px solid var(--ink)`，格子 `background: var(--paper)`。
  这是分区的唯一手段；格子内部行分隔用 `--hairline`，不再套边框卡片。
- 格子标题行：左 18px/800 标题，右等宽 11.5px 次要信息或文字链接。格子内边距 14px 20px。
- **网格纸**只用于「图」：拓扑、泳道等画图区域的底，`background-image` 两层 1px `--grid` 线、间距 20px。文字区不用网格纸。
- **读数格**（A4）：驾驶舱右下角「系统读数」，每格「等宽小标签＋15.5px 等宽值」，要看的那一格黑底反白（第 6 节）。
  带图名的标题栏组件 `TitleBlock` 仍在组件库里，驾驶舱自 T-195 起不再用它。
- 巨号只在每页出现一次；每页至多一个大号读数区。
- **间距**（T-191）：主档是 4 的倍数，`--space-1`…`--space-8`、`--space-10` ＝ 4…32、40px，新写的间距用主档。
  半档 `--space-0-5`／`-1-5`／`-2-5`／`-3-5`／`-4-5`（2、6、10、14、18px）只收现有的值，不再往里加。
  `padding`、`margin`、`gap` 不写 px 字面量，0 和 1px（细线补偿）除外；负的间距写 `calc(-1 * var(--space-N))`。
  和别的尺寸咬合、挪 1px 就对不齐的几何值（目录树的竖线、步骤连线、下拉箭头的留位）保留原值，
  逐条登记在守卫测试的豁免清单里并写明原因。
- **控件高度**四档（T-191）：`--control-touch` 44px（窄屏触控，第 5 节）、`--control-default` 40px（按钮、输入框）、
  `--control-small` 36px、`--control-compact` 32px（小按钮、工具条里的下拉）。等于这四个值的 `height`／`min-height`／
  `width`／`min-width` 一律引用令牌；顶栏 46px、各视图工具条 50px 这类版面尺寸不在此列。

## 5. 外壳

- 顶栏左：品牌格（16px 标志＋「工作台」，第 14 节）＋当前库名＋六个导航；「驾驶舱 N」角标与驾驶舱巨号同一口径、同一次黑板汇总读取、同一次策略草案读取（`cockpit/pending.ts` 的 `pendingCount`，T-162、T-195），标志的影子和标签页图标也看这个数。顶栏右：**状态胶囊**＋**⌘K 入口**（250px 等宽描边框「⌘K 跳转、搜索或执行动作」）＋**更多**。账户、最近删除、内存草稿与「跟随系统／浅色／深色」都收进更多菜单；草稿和文件操作待核对的提醒显示在更多按钮及其读屏名字上。
- **状态胶囊**把新鲜度、本机健康、会话三件事收成一个（A 轮先做前两件与数据提示，会话一项在 C 轮接入）：全部正常显示 `■ 正常`；否则显示最严重一项，如红色 `[ 同步偏慢 ]`。
  点开是一个浮层，逐项列出三块的原文与「重新核验」动作（原 `FreshnessNotice`、`HealthPanel` 的内容挪进来，一字不少）。
  **不再在每页顶部挂新鲜度横幅，不再在每页底部挂「数据提示」**：诊断信息挪到各自所属的格子里，或进胶囊浮层。
- 窄屏（<760px）：顶栏一行保留品牌格、**当前库名**、胶囊、⌘K 图标和更多，高 49px。360px 以下库名另起一行保证可读；760～959px 不另排第二行。底部固定六格导航（44px 触控高度），只在驾驶舱格显示待处理数；12 列网格收成单列。巨号按第 6 节的宽度规则缩小。
- 更多是非模态展开区：Esc 收起并还焦点，点外面或焦点离开也收起；点入口先收菜单、把焦点交给更多，再开对话框，关闭对话框后焦点回更多。对话框里的 Esc 不收菜单；切外观不收菜单。状态浮层带路时先展开更多再聚焦账户。入口组件一直挂载，⌘K 在菜单收着时仍能打开最近删除。
- 外观只在本机存储 `studiolo.theme.v1` 记 `light`／`dark`，跟随系统删键；标签页间同步。`index.html` 在样式之前引用 `/assets/theme-boot-<8位内容哈希>.js`，应用启动前先套偏好，不增加内联脚本或放宽 CSP；存储不可用时只在本页生效。
- **当前库名**（工作台 `source_label`）在任何宽度下都显示在品牌格右侧（等宽 11.5px，超长省略但 `title` 给全名），用户始终知道在看哪个库（承接 T-117）。
- **项目入口不许静默截断**：凡是只显示前 N 个项目的地方（⌘K 项目组；驾驶舱自 T-195 起不摆项目表），必须同时给出「全部 N 个项目」入口并写明总数（承接 T-117）。

## 6. 驾驶舱

画布「A 进阶」稿即布局（T-195，2026-11-12；1440×940）。一张图纸，1px 墨线外框，左 8 列、右 4 列，上下两行四格；
够宽（内容区 ≥ 1248px）时图纸上沿画 01～12 的标尺、图纸底画 12 等分的淡线，网格是看得见的。

1. **左上「等你处理」**：巨号和「件事等你处理」同一行，旁边是类型分布和「最久的已等多久」，右端是「等了多久」的刻度图例。
   下面一列队列，一行一件：序号与类型、标题与出处、等了多久、去处理。三路并成一列——
   黑板里等你的任务（待验收／待修订／待再次确认，从最后一次进展算起）、策略里等你的提案和草案
   （待复核、已校验可发布；被同一提交者更新的草案挡住的较早那份不算；从提交算起）、工作台待办（接口不带时间）。
   带时间的排前面、等得最久的在最上；不带时间的接在后面。
   - **选中行**：浅纸色底、上下墨线、黑底序号、标题 18px/700，多一行事实（进度／校验结果／出处）、一个实心主按钮——
     全页唯一的黑色实心按钮——和旁边的文字按钮「稍后」，再往下是就地展开的细节。其余行标题 15.5px/500，行尾是文字链接。
     桌面缺省选中第一行；小于 760px 的手机缺省不展开，先显示完整队列，点标题才展开；只在首次打开时判宽度，转屏不重置选择。点哪一行的标题就选中哪一行，再点一次收起。选中的那一件不在队列里了（处理掉了），
     改选顶上来的那一行——它原来那个位置上现在的那一行，原来排最后就选新的最后一行——不跳回第一行（T-200）。
   - **一行一个动作**：去协作页看那条任务、去策略页的「待处理」并选中那一份草案（`panel=pending&item=<草案号>`，第 17 节）、
     打开原文。策略草案的行还能就地批准、退回（下面「就地批准、退回」）；键盘流见第 16 节。
   - **就地细节**（T-197）：选中行里一条细线之下，每段一个等宽小标签带条数，下面一条一行——
     策略草案列校验问题、扩大项（■ 加「扩大」两个字）、收窄项（□）、改动条目（＋／－／～）；黑板任务列写域（它占着的路径）；
     工作台待办不列（接口只给标题和出处，出处已在事实那一行）。每段最多 6 条，多的写明还有几条；一截文字最长 96 个字。
     只读、不带任何动作，**不用红**（扩大项在策略页是红的，驾驶舱的红只给下面说的三处）。
     黑板任务不列回执：汇总接口里只有已结束的任务才带回执，等你的任务都没有。
   - **就地批准、退回**（T-200；`web/src/cockpit/InlineReview.tsx`，判断和措辞是纯函数 `review.ts`）：选中的那一行是策略草案时，
     就地细节下面一条细线，线下两个按钮「批准并发布」和「退回」（主人自己交的草案叫「撤回」）；黑板任务、工作台待办的行没有。
     按钮的读屏名字带对象名，和这一行的标题同一个叫法（下线申请是「下线能力集 claude」）。写动作只走第 17 节那一份共用流程。
     - **批准**先核对两样，一个接一个各读一次：现在生效的内容（`GET /api/v1/policy`）、二次认证状态（`GET /api/v1/auth/state`）。
       草案的校验报告是照现在生效的内容算的（报告的基准摘要 `base_effective_hash` 等于现在的生效摘要）才展开执行预览，
       文字和策略页是同一个函数；确认才发请求，请求里的 `expected_effective_hash` 用**报告的基准摘要**——人看到的扩大项
       是照哪一份算的，就按哪一份提交，对不上由服务端 `hash_mismatch` 挡下。
     - **报告旧了**（校验之后生效内容变过，比如刚发布了别的草案）：不出预览，写明原因，多一个「重新校验」按钮并把焦点交给它；
       校验完焦点回到「批准并发布」，人看过新结果再按一次。校验没通过的草案不再算「等你点头」，会离开队列，
       结果那一句写明是哪一份、去了哪里。还没有校验报告的草案同样先「校验」。
     - **发布不了的入口**：本入口没有一次性验证码路径（策略状态或因子状态这么说）、本页没有受控会话——写明原因，不出预览，
       退回照常能用。核对没读成：说明预览没有展开，再按一次重试。
     - **预览开着时就地细节全部列出**（问题、扩大、收窄、改动），不截到 6 条：要点头的东西得先看全。驾驶舱里不画能力差异表，
       要看「现在／改后」去策略页（主按钮还在）。

## 10. 新接口 `GET /api/v1/board/overview`

跨项目只读汇总，供驾驶舱与协作拓扑一次取全。完整契约在 [`../contracts/board-overview.md`](../contracts/board-overview.md)（随实现落盘）。

- 查询参数：`window_hours`，整数 1–168，默认 24；其他参数一律 400（`deny_unknown_fields`）。查询串提取用 `Result<Query<_>, QueryRejection>`，畸形或越界都走 `crates/local-server/src/history.rs` 的 `bad_query()` 同款 400 中文 Problem（与 T-113 横向修法一致）。
- 未启用黑板 404；许可忙 429；与 `/api/v1/board` 相同的鉴权、许可与策略哈希。
- 响应（字段名 snake_case，前端用封闭解码器，多一个或少一个字段都算无效）：

```json
{
  "generated_at": "2026-09-22T19:31:00Z",
  "window_from": "2026-09-21T19:31:00Z",
  "window_to": "2026-09-22T19:31:00Z",
  "policy_hash": "<hex>",
  "items": [
    {
      "id": "<task id>", "title": "前端全面重设计", "project": "项目/Studiolo",
      "status": "running", "parent": null, "adapter": "claude",
      "holder": "<instance id or null>",
      "holder_lineage": [{ "id": "<instance id>", "agent_type": "claude" }],
      "paths": ["web/**"],
      "attempt": { "phase": "running", "worker": "<worker>", "active": true, "lease_until_ms": 0 },
      "progress": { "tools": 12, "edits": 3, "last_progress_ms": 0 },
      "receipt_status": null
    }
  ],
  "items_truncated": false,
  "events": [
    { "at": "2026-09-22T19:31:00Z", "project": "项目/Studiolo", "task_id": "<task id>",
      "action": "<action>", "phase": "<phase>", "attempt_id": null }
  ],
  "events_truncated": false
}
```

- `items`：所有未结束任务，加上窗口内有事件的已结束任务；最多 500 条，超出置 `items_truncated`。`attempt`/`progress` 可为 `null`，
  `receipt_status` 为 `null` 或 `completed|failed|stopped|abandoned`。
- `events`：窗口内全部项目的任务事件，按 `at` 升序，最多 1000 条（保留最新的），超出置 `events_truncated`。
- 时间戳是 RFC3339 UTC，**可带小数秒**（服务端 `jiff` 输出带小数），解码器必须接受；`generated_at` 等于 `window_to`。`items_truncated=false` 时每条事件的任务都在 `items` 里且项目一致；`events_truncated=false` 时每个已结束项至少有一条事件；`items` 按（project, id）码点序严格递增。假数据也按这三条构造。

## 11. 动效与可达性

- 动效只用于反馈与状态变化：悬停背景色 120ms；`ui-button`、`outline-button`、`icon-button` 按下缩到 `scale(0.97)`，100ms ease-out，禁用按钮不缩。浮层出现 120ms 透明度＋4px 位移，视图切换直接切不做过场。
  拓扑选中、胶囊展开不做弹簧。`prefers-reduced-motion: reduce` 时全部取消位移只留透明度。
- 驾驶舱队列（T-197）另有三段，都用强一点的缓出曲线 `cubic-bezier(0.23, 1, 0.32, 1)`：新来的行自上方 8px 淡入 200ms；
  按了「稍后」或已批准、退回的行上移 8px 淡出 160ms 再挪走；巨号从一个数变成另一个数时滚动 200ms（变大从下往上，变小从上往下）。
  **键盘换选中行（J／K）不做动效**：按得快，动效只会拖慢；淡出还没走完就来了下一个键，先把那一件落定再处理，不让人等动画。
  进场用 `@starting-style`，只对带 `data-live` 的列表生效——三路都读完之后才打上，所以首屏和手动刷新后重新列出来的行不算新来的；
  巨号只在「数变成数」时滚，「—」换成数不滚。时长和曲线定在 `cockpit.css` 的 `.cockpit-queue` 上，不用 `transition: all`。
- 审批离场保留原位、同一个 key 的收起影子行，`inert` 且 `aria-hidden`，不参与计数、选中与键盘顺序；焦点立即交给下一件，不等动画。动画结束或 400ms 兜底后撤掉；减少动效时只淡出。
- 焦点环：2px `--ink` 实线外偏 2px；在黑底块上用 `--on-ink`。
- 对比度：正文 ≥ 4.5:1（两套主题都测）；红色只配文字或形状，不做唯一信号。
- 图标：巨号、方块、圈号、箭头就是主要图形语言；保留现有 `Icon` 组件的线条图标用于按钮，1.7 描边不变。

## 12. 不变量（改视觉时不许动）

1. 所有接口解码器保持封闭：部分或不一致的响应绝不当成空数据显示。
2. 认证请求在途 ≤ 2（`requestJson` 闸门，BUG-017/ADR-022）；会话每日复核一次（T-104）。
3. BUG-011（⌘K 监听）、BUG-015（位置进 hash）、BUG-016（dev 下策略动作）三处修法保留，对应测试保留并通过。
3a. 前端 ESLint 开启类型化 promise 规则（`no-floating-promises`、`no-misused-promises`、`await-thenable`，承接 T-118），新代码不许违规。
4. 外观偏好只记固定枚举，不存正文、路径、凭据或搜索词。首屏主题脚本必须是同源带内容哈希的外部文件。
4a. 不加载任何远程资源；不写 `<style>` 标签（CSP `style-src 'self'`），样式一律进 CSS 文件，组件自己 `import` 自己的 CSS。
5. 开发用假数据（`STUDIOLO_FIXTURES=1`）只在 `vite serve` 下生效，生产构建里不得出现。
6. 显示的每一个数都来自接口；拿不到就显示 `—` 和原因。
7. 页面只声明一个图标地址（发布检查 `scripts/check-preview.py` 只认一个），其余图标文件由脚本在运行时换上（第 14 节）。
   svg 一律带 `?no-inline` 导入：小文件默认会被内嵌成 `data:` 地址，而 CSP 是 `img-src 'self'`。
8. 自动刷新（第 15 节）不带 `?refresh=true`，同时在途的请求最多 1 个，页面上 5 分钟没有操作就停——
   前两条护着服务端（BUG-035、认证入口只收 2 个），后一条护着会话的闲置登出。

## 13. 规则（T-160，ADR-026）

规则的唯一母本是策略平面 rules 类的生效版本，规则名（`subject`）就是 `_规则/` 下的文件名；「哪类 AI 能读哪条规则」只看各类型能力集的
`read.rules_whitelist`，**缺字段即零规则**。人这一侧永远全读。不加新接口：只用 `/api/v1/policy`（生效条目带版本号）、
`/api/v1/policy/versions/{n}`（取正文）与 `desired`／`validate`／`withdraw`／`activate`。代码在 `web/src/rules/` 与 `web/src/views/RulesView.tsx`。

- **子标签**（与协作同一版式，红色 3px 下划线表示当前）：**列表 · 编辑 · 读权限**；右侧等宽汇总「N 条规则　M 类 AI」。
  位置：`view=rules`，`panel` 为 `edit`／`access`（列表记 null），编辑时 `item`＝规则名（空为新建）；换面板不清 `item`。
  规则名是标识不是内容，可以进 URL；正文与草案正文绝不进 URL。
- **列表**（默认）：一行一条规则——名（点开进编辑）、生效版本、生效时刻、读者（名单里列了它的 AI 类型，没有写「无」）、
  未发布草案（校验未通过与 AI 提案待复核是红色方块，自己的草案是空心方块）。只有草案的新规则、只出现在读名单里的规则也列出，
  版本写「未发布」。格子标题行右侧是「新建规则」。
- **编辑**：左源码（`MarkdownEditor` 受控）右预览（`MarkdownPreview`），两者按需加载。已有规则以最新的未发布草案为底，
  没有就用生效正文；新建先填规则名，前端预校验与后端 `validate_rules_subject` 同口径（以 `.md` 结尾、≤128 字符、不含 `/`、
  不以 `.` 开头、VaultPath 能接受）。「保存为规则草案（不发布）」＝提交 desired；下方一格是最新草案的校验报告
  （`PolicyReport`：差异与扩大项）和三个动作：发布（先展开执行预览，确认才发请求；被 403 `reauthentication_required`
  挡下时就地弹二次认证，认证后原样重试同一次发布）、校验（按当前生效内容重新校验）、撤回草案。编辑区有未保存的改动时不许发布。
  这一套动作和策略页是同一份（`web/src/policy/usePolicyActions.ts`，第 17 节）。
- **读权限**：矩阵行＝规则、列＝AI 类型（能力集 `subject`），格里是开关：实心墨色方块＝可读，空心浅框＝不可读，虚线框＝待发布。
  改一格＝为该类型提交一份能力集草案，**只改 `read.rules_whitelist`，其余字段与键顺序原样保留**；列头写能力集版本与
  「未设（零规则）」「名单读不出」（红字）「有待发布改动」「已撤销接入」。一列已有你提交、还没发布的能力集草案时按草案显示，
  下方「待发布的读权限改动」给出报告与发布／校验／撤回。再改这一列的格子会在这份草案上追加（交新草案、撤回旧的），
  一轮发布可以改好几格；改回生效原状则只撤回草案。只有名单读不出时才不让改（T-160g：原先有草案即锁列，每轮只能改一格）。
- **状态**：读取中是占满一格的读取条；未接入策略平面（404 `policy_plane_absent`）写「未接入策略平面」；任一读取失败、
  或版本记录与生效条目对不上（版本、类别、对象、摘要），整份作废并显示原因与「重新读取」，绝不把部分数据当空数据。
  能力集名单读不出的类型不计入读者，并用红色方块写明。
- **窄屏**（<760px）：网格收成单列；列表按规则分组、每个事实带原列名；矩阵同一份表格改排成按规则分组的开关列表，
  每个开关带类型名；控件 44px、输入 16px 字。
- **⌘K**：「规则」视图跳转与「新建规则」（只打开空白的编辑面板，不直接提交或发布）。

## 15. 自动刷新（T-196）

驾驶舱和协作页的拓扑开着就自己更新。别的视图、协作页另外三个标签不自动读。

- **什么时候读**：四样都满足时每 20 秒安静地重读一轮——当前视图是驾驶舱或协作拓扑；页面看得见；没有任何弹层开着
  （阅读器、编辑器、草稿架、⌘K、验证码、会话、最近删除）；最近 5 分钟内页面上有过操作（指针、按键、滚轮、触摸、切回页面）。
  条件重新满足时，数据不到 20 秒不读，超过就立刻补读。
- **为什么 5 分钟没操作就停**：服务端的会话按最后一次请求算闲置期限，每个请求都把它往后推；自动刷新要是不停，
  开着没人管的页面永远不会闲置登出。停着时在「读于」那一处写「有一会儿没操作，自动刷新先停着」，一有操作立刻恢复并补读。
- **读什么**：工作台快照、黑板汇总、策略草案，在驾驶舱上再加驾驶舱那一份本机健康。一个接一个发，自动刷新同时在途的请求最多 1 个
  （认证入口只收 2 个，另一个留给人点的动作）。快照一律读 `GET /api/workbench`，**不带 `?refresh=true`**：
  那个参数会让服务端把整库重新派生一遍（BUG-035）。本机没装黑板、本入口没装策略平面时，那一路不读。
- **安静**：重读期间不显示读取中，巨号不变成「—」；读成了换上新数，内容没变就什么都不重画。
- **没读成**：数据留着上一次的，在「读于」那一处写「自动刷新没成功：原因」和「现在重读」。一轮里任何一路没读成，
  下一轮的间隔加倍，最长 5 分钟，读成一轮恢复；每一路限时 10 秒。手动刷新和各处「重试」不变：先显示读取中，不拿旧数冒充。
- **「读于 N 秒前」**：驾驶舱在「系统读数」标题下那一行，协作拓扑在标题旁「截至」之后。自己走字（不到 1 分钟每 5 秒一跳，之后按分钟），
  悬停提示里是确切时刻和上面的规则；不是 live region，不逐次念。手动刷新读成也算一次。
- **协作拓扑**切回标签时不重读，看到的是最多 20 秒前的数，旁边写着多久前。
- **原文阅读器里的「刷新工作台」不变**：仍然关掉阅读器（M1 定的：旧快照的来源不拿新内容冒充）。阅读器开着时自动刷新不读，
  所以正在读的原文不会被换掉。
- 实现：调度是纯逻辑 `web/src/live/autoRefresh.ts`（时钟由调用方给，逐条有单测），有没有人在操作是 `web/src/live/attention.ts`，
  React 接线在 `web/src/live/useAutoRefresh.ts`；要跟着刷新的读取各自登记一个安静重读函数（`revalidate`）。

## 16. 键盘（T-197、T-200）

高频动作不用鼠标。全站一张快捷键表（`web/src/keys/shortcuts.ts`），「?」一览照它画，监听照它判，写的和做的不会两样。

| 键 | 在哪儿 | 做什么 |
|---|---|---|
| ⌘K／Ctrl+K | 任何视图 | 动作面板（第 8 节；不属于下面说的单键快捷键） |
| G 再按 H／P／D／C／R／S | 任何视图 | 去驾驶舱／项目／文档／协作／规则／策略，和点顶栏导航一样回到页首 |
| ? | 任何视图 | 打开快捷键一览；再按一次或 Esc 关闭 |
| J／K | 驾驶舱 | 队列里选下一件／上一件，到头不绕回；按住不放连着走 |
| Enter | 驾驶舱 | 去处理选中的那一件（和点主按钮一样） |
| H | 驾驶舱 | 把选中的那一件放到「稍后再看」，再按一次放回（第 6 节） |
| A | 驾驶舱 | 选中的是策略草案时，展开「批准并发布」的执行预览，再按一次收起；**点了「确认发布」才发布**（第 6 节） |
| R | 驾驶舱 | 选中的是策略草案时，展开「退回」（自己交的是「撤回」）的确认框，再按一次收起；**点了确认才撤回** |

- **跳转字母按英文首字母**：Home、Projects、Documents、Collab、Rules；策略的 P 已经给了项目，取 Strategy 的 S。
  不按拼音：拼音首字母有重复（项目、协作都是 X）。
  G 之后 1.5 秒内的下一个字符键归这次跳转：是表里的字母就跳，不是就作废——所以「G H」里的 H 不会落到「稍后」上，
  「G R」是去规则页，不会落到「退回」上。
- **不该响应的时候不响应**：焦点在输入框、文本框、下拉框、可编辑区（含 `role` 是 textbox／combobox／searchbox／spinbutton 的）；
  任何原生弹层开着（一览自己除外：它开着时只认「?」）；按着 Ctrl、⌘、Alt；输入法正在组字；带 Shift 的字母（「?」除外）；
  别处已经处理掉的键（`defaultPrevented`）。按住不放只认第一下，J／K 除外。
- **Enter 不抢**：落在按钮、链接、表单控件上是它们自己的点击。队列的 Enter 只在焦点没落在任何东西上、或落在队列这一格里时才算。
  J／K 选中之后焦点落到那一行的主按钮上，所以接着按 Enter 就是原生点击，焦点环标出位置，读屏念得出是哪一件。
  焦点在执行预览的框里时 Enter 不算「去处理」：人正在看要确认的东西，一下 Enter 不该把他带去别的页面（T-200）。
- **会写东西的键只到确认那一步**（T-200）：A、R 做的是替人点一下选中行里的那个按钮（键和鼠标走同一条路），
  打开的是执行预览或确认框，焦点落进框里；真正发请求的是框里的「确认」按钮，要人再按一次。不做「连按两下就发」。
  按键时焦点先落到那个按钮上再点（J／K 也是这样把焦点带进选中行的）：确认框收起后焦点回到这个按钮，
  不回到按键之前所在的地方（可能是顶栏、别的格子）；做完之后焦点立即交给顶上来的那一行，T-199 的不可交互影子只负责淡出，不延迟焦点。
  按钮不在（选中的不是策略草案）或者禁用着（正在做另一件、被更新的草案挡住），键没有反应；有一行正在淡出时也不响应。
  A、R 互相切换：一个预览开着时按另一个，换成另一个。
- **单键快捷键可以关**（WCAG 2.1.4）：一览底下的开关，只记在这台浏览器里（本机存储里一个固定的字，别的什么都不存）。
  关掉后 J／K／H／A／R／G／「?」都不响应，⌘K 不受影响；⌘K 里的「查看键盘快捷键」是把它开回来的入口。缺省是开。
- **一览**是原生弹层（2px 墨框，和别的浮层同一套出现与收起）：三组键位各一张小表，左边带框的键帽、右边一句话。
  它开着时自动刷新不读（第 15 节：任何弹层开着都不读）。
- **实现**：按键归谁是纯函数 `decideKey`（`web/src/keys/shortcuts.ts`，逐条有单测）；监听在 `web/src/keys/useGlobalKeys.ts`，
  window 上一个 `keydown`，**只挂一次**，回调放 ref、在布局阶段刷新（BUG-011 的修法）；各处经 `useKeyBindings` 登记自己的键位
  （现在只有驾驶舱队列）。它不理带 Ctrl、⌘、Alt 的键，和 ⌘K 的监听互不相干。
- **没做的**：批量批准（一次点头几份）；黑板任务的行内验收／退回；项目、文档、协作、策略各页自己的列表移动；自定义键位。
  上下箭头不拿来选行：页面要靠它滚动。

## 17. 策略页的三个子标签与能力差异（T-198）

策略页是最要紧的审批页。原来五块内容挤在一屏，现在一排子标签，每个标签只做一件事（代码在 `web/src/policy/` 与
`web/src/components/PolicyPanel.tsx`）。

- **子标签**（与规则、协作同一版式）：**现状 · 待处理 N · 提交**；右侧等宽汇总「生效 N 项　M 版」，全局撤销生效时
  三个标签上都写红色的「全局撤销中」（解除在「现状」里）。左右方向键换标签；换标签会收起打开着的执行预览。
  - **现状**（缺省）：生效中各项、生效中的撤销接入、全局撤销的解除；第二行「版本与回滚 ｜ 撤销接入」。
  - **待处理**：左草案队列，右「选中的草案」——来历、能力差异（只对能力集）、校验报告、发布／重新校验／撤回。
    没选时选第一份：只是把细节展开，不做任何动作。动作结果落在右边这一格。
  - **提交**：左表单（类别、对象、「撤销该对象」、正文），右「和生效中的差别」。正在写的内容由面板保管，换标签不丢；
    只在内存里，不进位置、不进本机存储。交成功后切到「待处理」并选中刚交的那一份，结果那一句跟着过去；
    没交成就留在「提交」，原因写在表单那一格。表单里的内容交完不清空。
- **位置**（`web/src/policy/policyLocation.ts`，纯函数）：`view=policy`，`panel` 为 `pending`／`submit`（现状记 null，
  不认识的值当现状）；`item` 在现状里是在读的版本号，在待处理里是选中的草案号，提交里不用。各标签记住自己选中的那一项
  （只记在内存里，发布、回滚、解除全局撤销成功后作废），位置里始终只有当前标签的那一项。位置里的草案号已经不在队列里
  就回到第一份，不报错、不改写位置。版本正文、草案正文绝不进 URL。

  「发布策略」至今写的是它）；`item=<版本号>` 在现状里读回那一版正文。
- **能力差异表**（`CapabilityDiff.tsx`；模型是纯函数 `capabilityDiff.ts`，字段的人话名字在 `capabilityLabels.ts`）：
  能力集的每个字段一行，三列「能力 ｜ 现在 ｜ 改后」，列头下的小字写明两边各是哪一版。
  - 名单（数组）按集合比：只看多了哪几项、少了哪几项，逐项写「新增」「去掉」（去掉的划线），先后和重复不算改动；
    一边整份都在、只是没写某个名单，按空名单算。单值写成人话（是／否）。这一边没有就写「—」。
  - 有改动的行用墨色、字段名加粗并写「有改动」。**不变的行先收着**：审的人先看改了什么，校验报告和发布按钮
    不被十来行没改的字段挤到一屏之外。汇总那一行写「N 项有改动，M 项不变」，后面跟一个文字按钮
    「列出不变的 M 项」（展开后是「收起不变的 M 项」，`aria-expanded` 照实），展开后按字段原顺序全部列出、
    不变的行颜色放淡。两边一样时只写「N 项都和现在一样」，不出表，要看再列出。展开与否只是这张表自己的
    显示状态，不进位置。不认识的字段照样列一行，名字用原路径。
  - **「扩大」「收窄」只照服务端校验报告标**（红色实心方块＝扩大，等你确认；空心方块＝收窄），标在报告说的那一项上；
    这张表自己不判方向——比如新加的项目已被名单里更宽的前缀盖住，服务端不算它扩大，这里也不标。
    正在写、还没提交时没有报告，就只说新增、去掉、有改动。
  - 任何一边读不出结构（不是 JSON、不是对象、空的）就不出表，说明是哪一边、为什么；审草案时指给校验报告，
    正在写时说怎么改。绝不猜。
  - 窄屏（<760px）每个字段一组：字段名占一整行，下面两格各带列名；表格语义靠显式的 `role` 保住。
- **对比基准**：待处理里是校验报告写的那一版（`current_version`，报告里的扩大、收窄就是相对它算的），没有报告就按
  现在生效的那一版；提交里是这个对象现在生效的那一版。没有生效版本时「现在」一列全是「—」，写明每一项都是新给的；
  撤销（没有正文）时「改后」一列全是「—」，写明发布后这类 AI 零权限。校验之后生效的版本又变了，写明这张表和报告
  照的是哪一版、列头写「校验时的 vN」，请人重新校验。基准正文没读到、读到的不是这类 AI 的能力集，只是这张表列不出来，
  说明原因并给「再读一次」；校验报告、发布、提交都不受影响。
- **版本正文只读一次**（`useVersionBodies.ts`）：在读的版本、差异表的基准、「从生效中的 vN 开始改」共用面板里的一份缓存
  （版本一经发布不会再变）；缓存只活在面板里，整页重挂从空的开始。「从生效中的 vN 开始改」对三类对象都有：
  把生效的正文放进编辑区（能力集和 skill 重新排成多行），覆盖已经写的；读回来时人已经换了类别、对象或勾了撤销就不填。
- **发布流程全站一份**（`usePolicyActions.ts`）：策略页、规则页都用它，驾驶舱的行内批准（T-200）也用它。
  同一时刻只做一件；发布、回滚、解除全局撤销、撤销接入先展开执行预览，确认才发请求；被 403
  `reauthentication_required` 挡下时就地认证，认证后原样重试同一个请求；每件做完重读整份数据。
  只读的动作（读一版正文）不重读。每做完一件写动作还发一次「策略平面刚被写过」（`PolicyChangedContext`）：
  App 那一份草案读取据此安静重读，顶栏「驾驶舱 N」角标不必等人回到驾驶舱。被二次认证挡下的没有发生，不发。
  人关掉认证窗口，这一次就没有发生，也不会再自动继续，提示改写成「已取消二次认证：…没有执行。」（三页一样）。
  - **给驾驶舱加的三个入口**（T-200，策略页、规则页的行为不变）：`previewWithdraw`——撤回也先出执行预览，确认才撤
    （策略页、规则页的「撤回草案」照旧点了就撤）；选项 `announce: false`——这一页的重读就是 App 那一份草案列表时，
    不再另发「策略平面刚被写过」，免得同一份列表读两遍；`validate`、`withdraw` 可以换掉做完之后说的那一句
    （驾驶舱的结果不落在草案旁边，要点明是哪一份、去了哪里）。
  - **驾驶舱按校验报告的基准摘要提交**，并且在展开预览之前先核对它就是现在生效的那一份（第 6 节）。
    策略页、规则页带的仍是页面读到的生效摘要，不核对校验报告是照哪一份算的（已知差别，没在这一片里改）。
